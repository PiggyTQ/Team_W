# 项目设计协作约定

- 产品范围以“完整的产品与功能规格”中的最新正式文档与正式增补为准。参考图片只提供设计借鉴，不自动扩充功能或推翻数据、权限和评估规则。
- 涉及完整 Web 的页面结构、信息层级、图表或日程布局改进时，先查阅 `设计参考与同步/设计参考与图片同步约定.md`，保留用户例图与逐图备注。
- 页面结构调整须同步可视设计图、实现和说明：先更新对应线框/页面设计图，实施后保存实际页面截图并核对，再更新页面状态和图片路径。细节修改保存受影响区域的对照即可，不要求无关页面重画。
- 明确区分“用户参考图”“待实现设计图”“实际页面截图”。未制作的设计稿标为待制作，不将参考图或实现截图冒称已确认的完整 Web 设计稿。
- 延续当前灰阶低保真约束，直到用户明确要求进入视觉深化阶段。没有依据的分数、趋势、实际耗时、日程时段保持未知；不要照搬例图数字。
- 不为例行设计同步另行征求分批确认；按已授权范围持续完成并维护文档。
- 信息分层先判断用户当前要完成的任务：主页面只常驻核心行动、必要状态与简短摘要，低频说明、历史记录、详细统计和版本管理按需展开。参考“六大弹出组件”选择最低必要打扰，不为凑组件新增弹窗；错误与关键影响就地可见，重要决策保留确认，精简后原功能入口仍须明确可达。
