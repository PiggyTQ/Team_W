# 三项功能补齐 v18

2026-10-17。本轮补齐上一轮核查明确的三项差异，继续使用原有 15 个主模板，没有新增主页面。以下“完成”指可交互的本地原型，不表示真实 AI、解析、岗位或课程服务已经上线。

## 入口与操作

| 功能 | 入口 | 已补齐操作与结果 |
|---|---|---|
| 教育经历 | 个人评估 → 资料与经历 | 添加、编辑学校/专业/学历/月份/在读，逐次本人确认，取消、修订历史、二次确认撤回；可选入通用或岗位简历 |
| JD 定向表达 | 我的机会保存岗位 → 职业报告 → 岗位简历 → 选择目标岗位 → 预览 | 保留要求原文，逐项关联确认经历，缺项保持未知；生成明确标注的模拟措辞，人工编辑、逐项确认、保存和输出 |
| 分阶段学习 | 目标计划 → 计划总览 → 分阶段学习与行动 | 默认理解准备/小范围实践/复盘表达，可改名、调整阶段顺序；任务设置阶段、高中低优先级、理由、前置依赖；资源链接与统一预算预检 |

教育与经历为同一资料来源中的不同事实类型，不把学校信息自动当成能力证明。教育可以独立选入简历，不强迫补造项目。技能沿用已有经历的本人确认机制。

## 连通规则

教育保存后可进入简历选择；简历选择页可返回编辑教育、经历与技能。岗位原文来自本人保存的研究卡，保留来源、日期与在招未核验标识。“SQL 或表格”仍保留为一个原要求，不擅自拆成必须同时具备。

每条岗位相关表达都关联所选事实版本，修改后必须重新确认。修订旧简历会重新进行 JD 对照，不直接沿用已批准的旧措辞。保存时检查事实和岗位原文是否发生变化。未关联证据的要求只显示未知，不生成能力陈述。

简历保存教育事实、经历、岗位和措辞的快照。后来的编辑不回填旧版；撤回教育后旧版停止导出，即便再次确认教育也必须另存新版。删除私人资料同时清除教育及简历快照。通用模板的预览与输出使用同一措辞规则。

阶段调整保留原 taskId、产物历史、状态、预计投入与岗位引用；所有任务共用当前周预算，不重复创建副本。阶段和优先级是本人可修改的安排，不是系统能力排名；阶段内按优先级展示，不声称自动排课。未分阶段的已有任务仍可管理。

前置任务未完成时，阶段卡的继续入口不可用并解释原因；其他开始入口提示返回分阶段计划，任务状态编辑和完成检查也防止绕过。允许查看已完成成果。循环依赖、依赖不存在、阶段逆序与旧版本覆盖均被阻止。取消/延期不冒充完成。
