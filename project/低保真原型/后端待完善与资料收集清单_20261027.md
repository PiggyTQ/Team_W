## 2. Agent 的建设与“训练”

第一版建议用已有模型 API，加上受审核的职业知识、检索、工具与权限边界，先搭建和评测 Agent。微调应在评测发现稳定问题后再决定，不把“先自训大模型”设为开发前提。[Agent 架构参考](https://www.anthropic.com/research/building-effective-agents)、[知识检索参考](https://www.anthropic.com/research/contextual-retrieval)、[评测参考](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)。这是针对本项目的实施建议，不指定模型供应商。

Agent 可先做一个主流程，按六类任务限定资料和工具：职业咨询、评估解释、计划推演、学习辅导、成果反馈、报告编辑。依当前分期，先接前四项中的职业咨询/评估解释/计划推演/报告编辑；学习辅导与成果反馈随课程和任务材料补齐再接。无需先训练六个模型。

程序侧仍需：模型接入、流式回答、取消/超时/额度控制、知识检索与引用验证、用户选定资料范围、窄权限工具、结构化草稿、版本检查与本人确认、独立评测。模型不能直接写画像、自动应用计划或把自述写成实际核验。

知识文档用于检索与引用；示范问答用于说明期望行为，必要时才用于微调；独立评测集用于检验效果。这三类分开保存，不把测试题混入训练示范。

## 7. Agent 示例的一条记录

- 场景：计划推演。
- 问题：“每周只有三小时，如何调整准备？”
- 输入：本人当前目标、确认材料、当前任务及已分配预算；明确哪些内容可以读取。
- 参考答复：说明取舍、缺项与假设，给有限备选，引用实际依据。
- 预期动作：生成待确认的调整草稿，返回业务页预览；不能直接改目标或计划。
- 检查重点：不超过总预算、不重复加任务、不假称课程已发布、不把未知能力写成不会、不编造引用。
- 审核：记录审核人、日期、通过/需修改及原因。

微调如后续确有需要，再从审核通过的示范中整理任务数据。不要直接拿全部原始招聘数据或私人聊天记录开训。

## 8. 第一批可以怎样交付

建议先以数据分析方向跑通一条完整链路，再扩展，不必同时补齐全部方向。以下仅为首轮工作量安排建议：

1. 一份确认后的职业档案和技能清单。
2. 从已有库挑选并审核 10–20 条相关岗位证据。
3. 两个含输入材料、参考产物及判定标准的实践任务。
4. 首批四类 AI 场景各 5 条示范，共约 20 条。
5. 另做约 20 条独立测试案例，包含未知/冲突/错误引用等情况。
6. 三组构造学生情境，以及一份报告、一份简历成品样例。

数量不是效果达标或训练充分的保证。更重要的是上下文完整、出处可核对、判定标准清楚。

另需以后确定的服务配置：模型服务/API 或自部署方案、发信渠道/邮箱、可选域名、文件/视频存储、异地备份目的地、管理与审核责任人。模型和邮件依用户当前安排暂缓；密钥由服务器配置，不放入资料包。
