# 统一流程导航

目的：每个主线页面都明确回答“从哪来、接下来去哪里”，不要求用户依靠顶部流程图猜测操作顺序。

- 桌面：正文下方常驻操作栏，固定占用独立布局行，不覆盖表单或正文；左侧为明确去向的上一步，中间为状态说明与必要补充入口，右侧为下一步。
- 手机：操作栏固定在底部，正文预留相应空间；按钮文字可换行。
- 上一步是产品流程的前一环节，不调用浏览器历史，直接访问页面也有稳定返回目的地。
- 页面内有步骤时先衔接内部步骤：资料经历 → 原文确认 → 四维与差距 → 目标计划；任务目标 → 尝试与反馈 → 贡献与表达 → 完成回执 → 行动复盘 → 职业报告。
- 浏览、返回或前进不确认材料、不生成分析、不创建任务、不标记完成。业务提交仍使用原页面的明确操作。
- 经历、计划、任务或报告不足时说明当前状态并提供补充入口；允许保留未知继续浏览，不强制完成所有前置条件。
- 实践优先进入进行中任务，其次为尚未开始的有效任务；取消、跳过、延期、完成的任务不会被当作下一待办。外部行动进入 U07 的实践详情模式（practice=taskId），先看实践目标，再记录实际结果，之后进入行动复盘。平台内任务与外部行动共用同一阶段语义，顶部高亮和底部按钮同步。
- 报告列表提供返回实践与回工作区；报告详情先返回报告列表。岗位简历与本人求职进展相互连接，AI 讨论保留回到原业务页的入口。
- 首页、首次设置、账户与管理工作区保留自身操作，不套用学生主线按钮。

验证：完整首次探索链路、已有任务、无材料、取消任务、报告列表与详情、简历与求职分支、AI 返回、状态保留，以及桌面和手机不遮挡。

实践链路修正：计划总览与执行列表的主要下一步均进入实践，不能直达报告。外部行动在 U07 模式内记录结果、贡献、实际反馈和私人局限；记录不自动完成任务。行动复盘承接同一 taskId 和用户结果草稿，保存后再进入报告。无任务先选资源或安排实践，停止任务回计划处理。
