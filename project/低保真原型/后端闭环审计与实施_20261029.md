# 后端闭环审计与实施

日期：2026-10-29。范围：现有 Web、账户业务数据库、规则服务和 Agent；保留现有视觉与业务入口，模型保持关闭，不产生新增模型费用。

## 已确认的基础与缺口

- 已有：真实账户、会话与 CSRF、按账户隔离的 SQLite 业务存储、全局乐观版本与幂等保存、课程正文和下载、职业目录、受限 Agent、预算账本、知识撤回及备份。
- 缺口：评估由服务端计算后仍要浏览器另存；任务的创建、提交、自检和完成主要依赖浏览器组装状态；后端缺少这些业务命令的原子回执。
- 缺口：已发生行动补录使用 0 小时，而服务器拒绝所有非正任务工时，导致真实账户补录无法保存。
- 缺口：业务动作响应丢失后，工作区同步没有独立的待恢复动作状态；需要用原命令和幂等键恢复，防止重复操作或未确认覆盖。
- 实际边界：PDF 本机文字提取、私人岗位卡和报告编辑已能存储；不应将这些重新包装成“尚未接后端”。后台管理页面在真实账户下为只读资料概览，没有可用的管理员身份和审核流程。邮箱找回未配置；实际代码运行与领域人员复核未实现，不能标为已核验。

## 实施决策

沿用模块化单体 Node + SQLite。新增业务命令服务，共用现有账户、事务、规范化校验和数据仓储，不另建用户或计划系统。浏览器继续保存输入草稿；关键动作由命令服务检查保存版本、对象版本、确认标记、预算、先修、课程版本和用途，再原子保存记录与回执。

命令覆盖：材料确认/撤回、任务创建/开始/提交/自检/有限范围完成、实际行动补录、评估快照、服务器报告编译。模型只能解释或提出提议，不接管这些规则。

回执按账户隔离，使用请求摘要、不可重复的命令 ID 和工作区版本；响应丢失用同一 ID 重试。回执保留有限时间，删除/清理账户同步清除，预算账本不回滚。

服务端生成的分析和已提交成果不能被草稿同步冒充或改写；本人自检与独立核验始终分开。兼容现有记录，并用真实 HTTP 与浏览器合成账户覆盖完整路径。
