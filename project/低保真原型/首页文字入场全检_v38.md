# 首页文字入场全检 v38

2026-10-19。用户指出“从了解一份工作到做出自己的成果”漏掉到达后文字浮现，并要求检查首页其他遗漏。沿用当前文案、灰阶、布局与v37轻滚切换，不回退既有循环拖动。

## 排查发现

流程原先只对整个节点做透明度处理，后续节点在成为当前步骤前便可能显示文字；流程、成果与职业展廊主标题也未接入已有的逐字揭示组件。原先静态内容只覆盖少数区域，动态内容则在挂载时就开始动画，屏外内容往往尚未进入视口就已播完。

## 逐板块检查与修复

| 板块 | 当前覆盖 |
| --- | --- |
| 首屏 | 保留标题逐字入场；补齐受众说明、介绍、动作区和滚动提示的视口触发 |
| 五种成果预览 | 标题逐字揭示；左侧解释、顶部阶段说明、画布内容进入视口才播放；阶段切换继续滑入滑出；手机线性展示同样覆盖 |
| 三个准备入口 | 入口标题、卡片标题/描述/产出进入时显示；选择后的说明通过方向过渡更新 |
| 四阶段流程 | 补齐标题逐字揭示；未到达节点的文字与产物保持隐藏，成为当前步骤后标题、简述、成果卡错开浮现；反向回看重新播放；节点下方解释同步过渡 |
| 十个职业方向 | 标题、介绍、卡片阅读内容随实际进入显示；保留匀速循环、鼠标拖动和松手续播，不因计数更新反复闪动文字 |
| 连贯案例 | 案例引导、侧栏、章节介绍、工具示意、工具标题、AI问题/答复/解释、报告、章节间提示均覆盖；卡片内滚动也按实际可视区域触发 |
| 使用说明与页尾 | FAQ标题、问题、展开答复、资料说明及结束文案、页尾动作覆盖 |

导航、表单选项和计数作为持续可操作的状态，不对每次数字或选项变化添加重复逐字动画；它们所属区域仍有首次进入效果。

## 触发与兼容

静态阅读组统一交给视口观察器，流程文字额外判断当前节点；移出后可重新准备，反向进入也能浮现。标题复用MotionText，动态面板复用useContentTransition，避免父子重复动画互相覆盖。新插入的AI答复等也会被登记。

动态面板动画在屏外暂停，实际进入后再播放；快速切换可中断，旧内容快照保持不可交互。仅使用transform与opacity，不改内容高度或滚动门槛。键盘聚焦时立即呈现对应可操作区域；减少动态效果直接可读，打印也强制完整呈现。

## 实测记录

`tests/home-text-reveal-check.mjs` 检查七个主要标题、四个流程阶段、未到达节点隐藏、到达浮现、反向回看、动态面板屏外等待、成果顶部说明、入口提示、工具切换、职业卡片、AI、FAQ、手机列表、英文与减少动态效果。

对初始首页264个标题、段落、列表说明等DOM文本节点做动画归属扫描（包含移动端替代内容及循环副本），排除关闭状态的答复后，没有未覆盖的阅读文本。运行时插入的答复和展开内容另有交互验证。[覆盖清单与结果](检查记录/首页文字入场全检_v38/验证结果.json)。

9项本轮浏览器行为及运行时检查、50项单元/模型测试通过。v37轻滚7项和鼠标拖动4项回归通过；构建通过，沿用当前约532kB主包体积提示。
