# 后端审查与业务建库

2026-10-27，服务器 `47.250.133.180`。本轮按用户授权审查并完善现有后端，保留现有账户。用户明确暂不接入模型与邮件服务；4 套课程、16 章、4 条视频由用户收集，本轮仅占位。

## 已上线

原后端只有账户、会话和限流 3 张表，业务状态仅在页面内存中。本轮扩展为 24 张表，采用现有 SQLite 数据库 `/var/lib/career-growth/auth.sqlite`，启用外键、WAL、事务迁移和安全删除。无须另起占用内存的数据库服务。

|范围|数据库与行为|
|---|---|
|账户|保留 users/sessions/rate_limits；增加改密、会话列表、撤销其他会话、密码复核与真实注销|
|个人材料|education_records、experience_claims、resume_imports|
|计划实践|plan_tasks、practice_reviews；预算、预计投入与依赖循环在服务器校验|
|报告与简历|career_reports、resume_versions、assessment_versions；保存现有前端快照，不冒充独立能力核验|
|求职研究|job_cards、job_events、saved_searches；仍不自动投递或对外发信|
|讨论与笔记|assistant_conversations、personal_notes；仅存本人记录，未接真实 AI|
|反馈|feedback_tickets；持久保存本人提交，管理处理台与真人回执尚未开放|
|保存一致性|account_workspaces 的账户版本、workspace_mutations 的幂等键、各记录自身存储版本|
|课程资料|courses 4 条、course_chapters 16 条、course_media 4 条；全部 placeholder，正文/视频URL/时长为空|
|运维|schema_migrations 记录数据库版本；security_events 只记操作代码、主体和时间，不记材料正文或密码|

所有私有数据以服务端会话主体查询，记录主键为 `(user_id,id)`。不信任浏览器提交的角色或 owner。保存请求同时绑定页面账号；同一浏览器在另一标签切换账号后，旧页面提交会被拒绝，不将原账户数据写进新账户。

前端接入自动保存与读取：保存中、已保存、失败、冲突分别显示；未读成功前不会用空数据覆盖账户。错误保留当前输入，支持重试、下载本页记录、确认后重载服务器版本。并行页面的旧版本返回 409，不自动采用最后一次写入。退出先保存，刷新或重新登录恢复记录。记录保存在账户库，私人正文不写 localStorage。

改密、清空和注销均需当前密码复核；清空/注销还需明确输入确认语句，注销需再次填写邮箱。改密轮换会话并撤销其他会话。清空只删本账户业务对象，保留账号；注销通过外键级联删除本账户在线数据。清空/注销与对应审计写入处于同一事务，写入中途失败时完整回滚；已验证故障注入场景。删除使用 secure_delete 并收敛 WAL 日志；不声称能擦除云盘硬件历史或已经由用户下载的文件。

## 课程占位

目录沿用前端现有 4 个稳定 ID：quality、ai-eval、log、restore。每套 4 个章节目录及 1 个视频位置。没有编写占位正文、伪造时长、播放地址、许可或已发布状态。页面只能查看待补充目录及收藏；不会产生阅读/完成记录，也不能从 API 绕过限制创建对应课程任务。手动外部实践不受影响。

后续收到材料后，再核对标题、正文、视频来源、使用许可和审核状态，接入实际阅读/播放。当前并未完成内容发布后台。

## 接口

|方法与路径|用途|
|---|---|
|GET /api/workspace|读取本人全部工作区状态与版本|
|PUT /api/workspace|按 actorId、baseVersion、mutationId 事务保存本人状态|
|GET /api/records/:collection/:id|读取本人指定业务对象；其他账户访问返回 404|
|GET /api/workspace/export|主动导出本人完整记录，包含私人记录，不含密码或会话令牌|
|GET /api/catalog/courses|读取待补充课程元数据；需登录|
|GET /api/auth/sessions|查看本账户有效会话，不返回会话密钥|
|POST /api/auth/change-password|复核密码后改密并轮换会话|
|POST /api/auth/revoke-others|复核密码后撤销其他会话|
|POST /api/auth/clear-workspace|复核密码与版本后清空本人业务记录|
|POST /api/auth/delete-account|复核密码、邮箱和确认语句后注销|
|GET /api/ready|数据库就绪检查，不返回私人数据|
|GET /api/system/capabilities|登录后查看当前服务是否已接入|

写接口检查 Origin、CSRF 和账号绑定。业务保存请求最大 768 KiB，单文本最多 200000 字符，每类最多 1000 条；超过限制会明确拒绝并保留本页输入，不截断数据。当前是兼容前端状态的事务保存 API，并非全部业务对象的独立领域命令服务。

## 备份与操作

`career-backup.timer` 每天约 03:00（服务器中国时区，随机延迟不超过 20 分钟）执行一致性备份。位置 `/var/backups/career-growth`，目录 700、文件 600，仅管理员可读。每次备份执行完整性、外键检查，并还原到临时库再次检查。托管备份采用 14 天保留策略，每日清理到期文件；包括升级前备份。备份仍在同一服务器，异地容灾尚未配置。

常用操作（在服务器源码目录 `/srv/career-growth/source`）：

```sh
node server/inspect-db.mjs
python3 server/backup-db.py
systemctl status career-auth career-backup.timer career-certbot.timer
node --test tests/business-api.test.mjs tests/business-store.test.mjs tests/workspace-sync.test.mjs
```

首轮源码包、旧前端发布目录和账户库升级前备份均保留。建库迁移已在既有库完成，未重置账户数据库。前端发布通过符号链接切换，旧发布可回退；数据库回退前需先评估升级后新记录，不自动覆盖新数据。
