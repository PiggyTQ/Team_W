## 本轮边界

注册、登录、会话查询、真实退出由服务器提供。其他工作区业务仍是演示；真实账户模式不读取旧原型的 localStorage 登录标记或私人材料。业务演示记录仅驻留当前页面内存，刷新、退出或换账号即清除，不把这些记录冒称为服务器业务数据。账户与密码哈希在服务器持久保存；浏览器刷新可恢复有效账户会话。后续应按正式对象契约逐项接业务 API。

邮箱仅作为账户登录名，尚未验证归属。缺少邮件发送渠道，找回接口返回明确不可用，不发送邮件、不声称已发送；账号删除后台尚未实现，原型中的本机删除按钮不等于注销真实账户。

## 格式与安全

- 邮箱去掉首尾空白并统一小写后匹配；最长 254 字符，本地部分最长 64，支持加号标签，限制点与域名标签格式。暂不接受国际化邮箱本地部分。
- 新密码 15–128 个 Unicode 字符，支持中文、空格、粘贴及密码管理器；不裁剪、不规范化、不自动改大小写；前后端共用同一契约。基本常见密码名单会拒绝，尚未接入完整泄露密码数据库。
- 登录只检验非空与最大长度；不对已有密码强加新注册规则。密码按原字符精确匹配。
- 密码通过 HTTPS 传输，以独立随机盐和 scrypt（N=131072、r=8、p=1）存储；每次密码操作约需 128 MiB，最多两个并行计算。数据库没有明文密码。
- 随机会话令牌仅存于 HttpOnly、Secure、SameSite Cookie；数据库保存令牌 SHA-256。登录轮换会话，退出撤销，闲置 30 分钟/绝对 7 天失效。会话查询不会延长闲置时间；实际键盘/指针交互节流刷新。
- 同源 Origin、跨站请求检查与 CSRF 令牌保护提交；SQLite 参数绑定；限制 JSON 为 8 KiB；IP/账户尝试次数持久限流。密码错误和未知邮箱统一返回 INVALID_CREDENTIALS。
- 返回目标必须为安全站内路径，不回 /auth 或管理区，不接受外链、反斜线、控制符。
- 密码仅由表单 DOM 读取到请求，不放 React 状态、URL、日志或浏览器存储。角色收到的只有状态与事件 ID；密码/显示密码/提交时保持遮眼，仅真实 INVALID_CREDENTIALS 触发原有错误动作。
- 提交防重复、超时可重试、错误保留当前输入、取消中止前端请求。格式问题就地提示，网络/服务问题不会冒充密码错误。

## 运行与位置

服务器：47.250.133.180，Ubuntu 24.04。Nginx 对外，账户服务仅监听 127.0.0.1:3001，以 career 系统用户运行。Node 24 LTS 下载校验 SHA-256。

- `/srv/career-growth/source`：前后端源码、依赖锁和测试；后续可在此开发。
- `/srv/career-growth/current`：当前前端发布的符号链接；`releases` 保留版本。
- `/var/lib/career-growth/auth.sqlite`：账户、同意记录、会话哈希和限流数据，仅服务用户可读写。
- `/etc/nginx/sites-available/career-growth`：当前网站配置。
- `career-auth.service`：账户服务开机启动、失败重启与资源限制。
- `career-certbot.timer`：每日两次检查短期 IP 证书，续签后自动重载 Nginx。
- `/etc/letsencrypt/live/career-ip`：证书与私钥，由 root 管理。

开发演示：`npm run dev`；真实认证构建：`npm run build:server`；后端：`npm run start:auth`。本地联调需设置后端 PUBLIC_ORIGIN，并通过反向代理提供同源 /api。不要把演示构建覆盖到真实认证的发布目录。

部署初次步骤见 deploy/。源码包排除 .deploy-auth、.env 本地秘密、数据库、历史检查与 node_modules。原有本机 SSH 密钥受口令保护，本次另用 .deploy-auth 中的专用密钥（已被忽略），不随网站发布。
