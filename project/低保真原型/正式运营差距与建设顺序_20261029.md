# 完整 Web 的正式运营差距与建设顺序

日期：2026-10-29。依据为当前本地代码和最近部署验收记录，本次未重新探测生产运行状态、读取生产个人记录或修改线上配置。

## 判断

已有核心业务闭环，具备组织受控试用的工程基础；尚不能据此宣布正式公开运营就绪。正式运营还需要可见的前后端协作、账户恢复、管理发布、容灾告警，以及真实使用质量和容量证据。AI 继续关闭，原累计 8 元模型测试预算不变。8 元不是服务器、邮件、存储等基础设施的总运营预算；新增收费服务须先说明费用并取得授权。

现有 Node 模块化单体与 SQLite 继续使用。先补运营能力和测量，再依据并发写入、锁等待和延迟决定是否迁移数据库；不预设微服务、Redis、向量库或多 Agent 为上线条件。

## 已有基础

- 真实账户、会话、安全 Cookie、同源/CSRF、账户绑定、密码哈希和请求限流。
- 按账户保存业务资料、版本冲突、幂等请求、13 类服务器业务命令、原子回执与响应丢失恢复。
- 材料确认与撤回、确定性分析、预算与依赖、任务成果版本、自检、有限范围完成、报告保存和导出。
- 四门已发布课程及素材下载，职业/技能/历史岗位目录；目录存在不等于实时招聘或审核认证。
- 个人上下文关键事件刷新、规则建议、反馈失效控制、导出与清理；新增建议接口尚无前端消费者。
- DeepSeek 适配、授权范围、知识来源约束、失败处理及累计费用阻断；模型仍关闭。
- HTTPS 配置、服务自动重启、每日同机一致性备份、14 天保留及恢复检查。

最近一轮证据：416 项自动测试，415 通过、1 跳过、0 失败；独立环境和生产 API 各 17 组、生产浏览器 10 组。它们验证工程链路，不证明真实学生效果、峰值承载或全面安全达标。首次截图字体等待失败及重跑限制保留在验收资料中。

| 优先级 | 工作 | 当前差距 | 验收要求 | 需要用户参与 |

| P0 | 将事件建议接到现有页面 | GET 建议与反馈接口已部署，src 尚无调用 | 目标/确认材料/任务变化后重新读取；草稿输入不请求模型；展示理由和来源对象；支持忽略/不相关；账户切换和旧版本请求不能串用；保留现有页面风格 | 通常无需额外资料；生产发布仍按原约定确认 |
| P0 | 邮箱归属验证和找回 | emailVerified 固定 false；recover 明确返回不可用 | 发信适配、一次性短期令牌、令牌散列存储、同一账户重置竞争控制、通用响应防枚举、频控、重置后会话处理、实际送达与退信验证 | 提供获准发信服务及发件域授权；密钥通过私密方式配置 |

| P0 | AI 受限试用和质量验收 | 密钥和调用链已有；关闭开关；真实学生和独立领域复核未完成 | 明确名单、外发同意、来源/未知说明、模型失败恢复；对材料撤回、否定条件、注入与串号回归；真实学生完成任务并反馈；仍保留预算硬阻断 | 开放试用授权、真实参与者；需领域判断时由实际人员复核 |
| P1 | 统一发布与数据迁移 | 已有迁移记录、增量部署和回退脚本；不同模块仍有启动建表，未见完整 CI 工作流 | 统一模块迁移登记及前后兼容策略；自动测试/构建/隔离环境/发布摘要/上线检查；代码版本可追溯；并行修改不覆盖；回退不恢复旧费用账本 | 仓库或 CI 服务外部接入如有需要再授权 |
| P1 | 内容更新与纠错闭环 | 46 条获准原创指引、历史岗位和课程已有；覆盖、时效及独立复核有限 | 来源、用途、适用对象、更新时间、版本、撤回；错误反馈能够转为修订和回归题；历史岗位不升级为当前在招；引用对应实际发布版本 | 特定数据源授权、实际审核人；公开官方资料整理和工程接入由工程完成 |

P0 表示建议在相应能力向公众正式开放前完成；不表示本次审查发现所有安全控制缺失。仅规则型平台可先保持 AI 关闭试用；若对外承诺 AI 助手，则应先完成 AI 受限试用验收。

## 按产品承诺决定的扩展

1. **原文件保存与解析**：现有本机 PDF 文字提取及结果保存不是原件上传。若承诺跨设备保存原 PDF/DOCX、扫描件 OCR 或成果附件，才补私有对象存储、文件大小/类型/签名校验、隔离解析与恶意文件防护、权限下载、删除保留与任务状态。不能将新增文件外发服务默认纳入既有 AI 同意。
2. **独立能力核验**：如果产品只做职业探索，可以继续如实标记本人自检。若承诺自动执行代码或认证能力，需要独立隔离运行环境、资源和网络限制、版本化评分标准及人工申诉；模型评价不能替代实际执行或专业认证。
3. **站内提醒**：事件建议接入后可增加去重、已读、忽略、频率和隐私设置。邮件/推送是独立渠道，不以后台反复调用 DeepSeek 来驱动提醒；未来需要异步发送时再引入持久任务与重试。
4. **数据库扩展**：先测现有单实例业务。只有出现实际写入竞争、需要多实例或明确的运维需求，再制定 PostgreSQL 等迁移方案；不能根据当前测试数量推断并发容量。

## 推荐顺序

先接建议消费和反馈，完成用户可感知的个性化闭环；同时在本地补运行指标、隔离容量测试和统一发布检查。随后接邮箱与管理发布，再完成异地恢复和故障通知。最后按获准名单开放 AI 小规模试用，结合真实使用记录修正内容与流程后扩大范围。上线更改始终先完成可验收候选，再按已有生产确认约定执行。
