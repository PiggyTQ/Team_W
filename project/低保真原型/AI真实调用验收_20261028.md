## 真实测试暴露的问题及修复

合成原文为“测试学生记录了一次 SQL 查询练习，未进行独立能力核验”。v1 模型将其改写为“自述学生完成了一次 SQL 查询练习”。引用编号确实存在，但“记录”被升级成“完成”，超出了材料直接支持范围。

本地 Prompt 更新为 `career-readonly-v2`，新增 `AI_UNSUPPORTED_FACT` 守卫。首版 `fact.text` 只允许来自所引批准知识或本人确认材料原文的连续片段，而且每个所引来源都必须包含该片段。建议、问题分型，预算数值继续由业务程序负责。客户端可写的 `verified:true` 不会进入模型证据。

新增回归覆盖“有效引用 ID 仍不能把记录升级成完成”、无关来源混入及计划估计被改写成模型事实。v2 对同一案例真实复测通过，保留原错误响应作为失败记录。

逐字引用仍不能自动证明上下文完整、否定或条件没有被遗漏，也不能证明建议本身正确。正式开放前仍需人工支持性与错误类型评估；此次没有生成准确率或普遍有效性的结论。

## 下一增量的必要条件

前端接通前应完成三项已有代码边界处理：

1. 原资料选择和隐私文案声明“没有外部传输”，此前模拟授权不能自动变成向 DeepSeek 外发的同意。须明确供应商、字段、片段和用途，并记录新同意版本。
2. 当前整个工作区自动保存。等待中的消息、草稿、模式和返回路径变动可能让 revision 增长，导致服务器丢弃真实回答。请求状态应与持久业务状态分开，先 flush，再用确认快照构包，结果经账号、上下文和请求守卫后一次性保存。
3. 真回答不得自动创建当前模拟提议。撤回或删除引用材料时，消息、引文和笔记的派生正文须统一失效；没有可用真实知识时保留信息缺口。

已有工程接通点是 `main.jsx` 共用发送入口、`AssistantChat.jsx`、`AlignmentDialogs.jsx` 和 `useServerWorkspace.js`。后续先在本地以测试桩完善这些行为与局部设计同步，再进行明确范围的生产发布评审。
