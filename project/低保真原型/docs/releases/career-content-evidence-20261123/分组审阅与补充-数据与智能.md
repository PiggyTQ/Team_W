## 4. 可直接落地的职业内容：数据分析

以下是可直接进入职业介绍的中文稿。细分以工作侧重组织，不能标成国家统一岗位清单。原报名案例及其产物继续放在“体验一种代表任务”之下。

### 职业定义与边界

数据分析围绕需要作出的业务判断，整理数据、定义指标、选择分析方法，并把发现、证据和限制交给使用者。工作既可能是持续维护经营报表，也可能是针对一次异常、用户行为或业务策略开展专项分析。分析的价值来自让他人理解并使用证据，而不只来自图表数量。国内“商务数据分析师”与这里的业务分析方向有关，但并不覆盖所有行业中名为数据分析的岗位；国外BI分类也仅作相关职业活动参考。[国内职业标准](https://osta.uestc.edu.cn/shangwushujufenxishiguojiazhiyejinengbiaozhun.pdf)、[O*NET BI职业活动](https://www.onetonline.org/link/details/15-2051.01)

与数据工程相比，本方向更关注指标如何回答业务问题；与模型研究相比，并非每个任务都需要训练预测模型。实际岗位可能同时承担报表建模、取数与分析，边界要结合团队分工确认。

### 完整工作链

1. **把问题说清楚。** 谁要作出什么决定，观察哪个对象、时间范围和指标；先核对含义，再选工具。交付需求与指标约定。
2. **确认数据能否使用。** 了解来源、字段、访问范围、更新节奏和已知缺口；保存取数条件与清洗记录。
3. **形成可比较的数据。** 处理类型、缺失、重复和关联；检查汇总是否与明细、不同来源口径一致。交付可复算查询或工作表。
4. **选择匹配问题的方法。** 先描述分布、变化和分组差异，再决定是否需要进一步建模或验证；把观察与原因假设分开。
5. **交付解释。** 用表图、报表或分析报告说明发现、依据、限制、建议核对的事项；让业务人员能够提出异议。
6. **跟进使用与维护。** 记录最终采用的口径、问题处理及报表更新；后续结果不符合预期时复查数据与假设。

这是一条本站整理的工作框架，任务可往返，团队也可能分别承担各环节。[O*NET BI任务](https://www.onetonline.org/link/details/15-2051.01)、[Power BI角色与方法范围](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/pl-300)

### 准备、成长与工作环境

- **先准备能展示的基础。** 用一份小数据说明统计单位、处理过程和限制；掌握表格或SQL的基本清洗、关联和分组；用基本统计概念解释比较是否成立；能用业务语言写清结论。Power BI等是可选工具路径，PL-300不是所有分析师的入职条件。[SQL窗口排序方法](https://www.postgresql.org/docs/19/tutorial-window.html)、[PL-300范围](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/pl-300)
- **用责任扩大说明成长。** 起点可以是按已确认口径完成并复算一份结果；进一步能够独立澄清问题、协调多个来源、说明替代解释；再进一步负责跨团队指标、分析方法与长期复用。这里是本站学习建议，不对应统一年限、学历、职称或升职承诺。
- **环境因场景改变。** 持续报表更重视稳定定义、刷新与维护；临时分析更需要迅速澄清问题和资料缺口。两者都包含沟通与复核。行业知识、数据访问方式和交付节奏会改变工作方式，不根据国外职业数据推断中国所有岗位工时。

### 代表任务如何接回现有案例

报名案例展示的是“指标定义—数据处理—变化定位—结论边界”这段工作。它没有访问量、用户身份归并或实验输入，不能由此判断转化率、独立报名人数、广告效果或因果关系。建议在案例末增加一句：“如果你更关心持续报表，可继续了解数据模型、刷新与权限；如果更关心产品行为，需要进一步了解采集口径和验证设计。”这是后续方向提示，不自动生成任务。

## 5. 可直接落地的职业内容：人工智能

### 职业定义与边界

人工智能工程把适合的算法、模型、数据和软件系统组合起来，解决具体使用场景中的识别、预测、生成或辅助决策问题。除了得到一次可用输出，还要考虑实现、验证、交付和后续运行。国内2021职业标准包含芯片、平台、自然语言及语音、视觉、应用集成等方向；本站问答体验选取的是应用集成中的一段评测工作，不能代表全部人工智能职业。[国内人工智能职业标准](https://www.beijing.gov.cn/zhengce/zhengcefagui/qtwj/202204/W020220417422568219867.pdf)

### 完整工作链

1. **判断问题是否适合AI。** 明确用户、任务、使用条件及错误后果；比较规则、搜索或人工处理是否已经足够。
2. **准备可用输入。** 确认资料、数据与模型的来源和使用范围；定义输入、预期输出及测试样本，不让训练/调试材料冒充独立测试。
3. **开发与集成。** 按任务选择现有模型或训练方案，组织数据处理、模型调用与业务接口；保留配置和版本。
4. **验证效果与限制。** 依据任务检查结果质量、失败类型、运行表现及适用范围；开发人员之外的领域人员参与复核。
5. **形成交付条件。** 说明配置、依赖、操作方式、人工接管和异常处理；发布是否可接受由相应负责人决定。
6. **在运行中继续评估。** 跟踪反馈、数据或场景变化，保留事件与更新记录，必要时回退、停用或重新验证。

团队按角色分工承担上述工作，不要求每个人都自研芯片、训练大模型并负责全部部署。工作活动范围参考国内职业标准；持续评估与运行风险参考NIST，后者不是国内任职或合规认证标准。[国内标准应用集成章节](https://www.beijing.gov.cn/zhengce/zhengcefagui/qtwj/202204/W020220417422568219867.pdf)、[NIST AI RMF](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.100-1.pdf)

### 方向差异与可能产物

### 协作、准备、成长与环境

- **协作。** 领域人员确认任务含义和错误影响；数据人员确认输入与更新；开发/平台人员处理接口、依赖和运行；评估及安全相关人员参与检查。具体团队可能一人兼任数种角色，需要把判断和责任写清楚。[AI生命周期角色参考](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.100-1.pdf)
- **准备。** 先能用程序处理输入、调用组件、保存版本并写测试；理解数据划分、基本统计与模型评估；能解释一个失败例为何需要补证据。深入模型、平台、芯片或应用集成，需要不同的数学、软件或硬件知识，不能把“会写提示词”当成整个工程基础。
- **成长。** 从按固定材料复现一段流程，到独立提出基线并组织评估，再到对复杂集成、交付和持续运行的约束负责。专业深化与组织协作均是可能路线；这不是把国家标准初/中/高级换成企业职级，也不以固定年限保证成长。

## 6. 可直接落地的职业内容：数据工程

### 职业定义与边界

数据工程围绕数据的接入、处理、组织和交付建立可运行的流程，让使用者知道数据从哪里来、含义是什么、何时可用以及失败时怎样处理。工作可能涉及批处理、流处理、数据仓库与平台支持。国内大数据工程技术人员涵盖处理、分析与管理等更宽范围；这里的数据工程侧重其中的数据处理与交付，并与数仓、数据库和平台工作交叉，不能简单视作一个统一职业编码。[国内大数据职业标准](https://zsgx.mohrss.gov.cn/uploads/2024-10-24/大数据工程技术人员国家职业技术技能标准.pdf)、[O*NET数仓职业活动](https://www.onetonline.org/link/details/15-1243.01)

### 完整工作链

1. **明确下游需要。** 确认一行代表什么、字段与来源、交付时间、使用者以及访问范围；形成契约与数据模型约定。
2. **接入与保留来源信息。** 按系统条件组织采集、批次或事件输入，记录版本与来源映射，处理缺失和异常输入。
3. **转换并组织数据。** 编写清洗、关联和计算逻辑，构建适合查询的结构；保留字段、模型和依赖说明。
4. **验证候选结果。** 检查契约、质量、内容和可用时间；设计测试以及问题定位所需的记录。
5. **调度与发布。** 组织依赖与重试，选择目标系统支持的发布方式，让下游读取完整、可识别版本的结果。
6. **维护与变更。** 监测任务和资源，处理失败、回填及上游变化；更新文档、权限与交接说明，确认下游影响。

这是按职业活动整理的通用框架；实时、离线、数据库及文件环境会采用不同实现，不由Airflow这一种工具定义整个职业。[数仓任务](https://www.onetonline.org/link/details/15-1243.01)、[国内处理与管理工作要求](https://zsgx.mohrss.gov.cn/uploads/2024-10-24/大数据工程技术人员国家职业技术技能标准.pdf)

### 常见侧重、产物与协作

| 工作侧重 | 重点约束 | 可能交付 |
| --- | --- | --- |
| 数据接入与批处理 | 输入版本、依赖、重复、缺失和补数 | 接入映射、转换代码/配置、调度与恢复说明 |
| 数据仓库与分析数据层 | 数据粒度、结构、指标含义及查询用途 | 模型、字典、来源映射、质量测试和可供下游使用的数据表 |
| 流处理 | 持续到达的数据及时间、迟到与恢复规则 | 处理逻辑、时间与状态约定、监测和恢复方案 |
| 数据平台与治理支持 | 共享能力、元数据、质量、权限及运行支持 | 平台组件/接口、元数据与血缘、访问和运维记录 |

这些是本站整理的工作侧重，实际职位可以交叉。国内标准为相关范围依据，O*NET数仓资料主要支持数仓侧活动；流处理的具体语义仍需对应技术资料，不能用本次固定分区例宣称已覆盖。[国内标准](https://zsgx.mohrss.gov.cn/uploads/2024-10-24/大数据工程技术人员国家职业技术技能标准.pdf)、[数仓活动与产物](https://www.onetonline.org/link/details/15-1243.01)

### 准备、成长与工作环境

- **准备。** 理解表、键、关联与数据粒度；用SQL或程序完成可解释的转换；用版本管理保存代码和配置；为异常输入、失败与重跑设计检查；了解元数据、权限与调度。更复杂的分布式或实时处理应在具体方向中深入，不把某一套工具当所有岗位必修。
- **协作。** 上游开发说明字段和事件变化；分析/业务人员确认粒度及可用要求；平台、运维或安全相关人员确认运行、访问和恢复边界。数据契约与问题清单应能让接手者知道谁需要处理什么。
- **成长。** 从维护一条约定明确的转换，到独立设计有测试和恢复能力的数据交付，再到协调多个系统的变更、成本与下游影响。这是责任范围递进建议，不直接等同官方等级或企业职级。
- **环境。** 同一团队可能既有计划内开发，也有失败、迟到数据与上游变更处理。日报批处理和持续流处理的时间要求不同；是否值守以及如何交接取决于岗位约定，不由“数据工程师”名称直接决定。数据量小也需要质量与恢复设计，不必为了展示职业而虚构大型集群。

### 接回现有重跑体验

保留b17/run1、retry、bad-retry及b18。让用户先说明输入批次与分区，再核对四个ID和channel，判断为什么“行数相同且主键唯一”还不够。任务设计可继续补一条开放问题：“如果下游已读到旧版本，改完的数据怎样被识别和替换？”把它作为设计讨论，不能把无执行环境的文字作答判成真实管道已经原子发布或端到端恰好一次。[Airflow固定分区与重试方法](https://airflow.apache.org/docs/apache-airflow/3.4.0/best-practices.html)、[PostgreSQL事务边界](https://www.postgresql.org/docs/19/tutorial-transactions.html)
