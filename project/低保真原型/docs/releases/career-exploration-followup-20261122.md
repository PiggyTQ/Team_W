## 如何收敛思路并落地

| 复核问题 | 已落实的行为 |
| --- | --- |
| 正常录入只有SQL等普通名字，不能进入相关材料 | 个人评估的已确认材料可展开“关联职业与具体技能”，选择最多3个相关职业及可选精确节点、保存或全部解除。职业页可见材料标题，材料筛选可用，空筛选提供明确关联入口 |
| 一个SQL标签可能误推整个职业 | 普通技能名仍保持原文。关联只表示相关任务自述，不产生准备度、评分或掌握；没有关联保持未知。明确空关联也覆盖旧career/内部前缀映射，确保可以解除 |
| 项目候选丢失职业身份 | createSkillCandidates保留原任务的有效career映射，来源taskId/attemptId照常保存；候选仍须本人确认才进入相关材料，精确节点由本人选择，不凭名字猜测 |
| 旧返回状态覆盖新搜索 | 只在相同结果条件下恢复旧滚动/焦点；明确新关键词、来源、分组优先。详情返回使用其URL条件，缺失时才沿用会话条件 |
| 按钮让人误以为继续同一个任务 | 当前职业页自带输入、步骤、预期小产物、检查及可保存/清空的体验草稿；下方明确“学习相关技能（另一套练习）”。现有课程内容和检验不换成职业案例 |
| AI原文/待审回答不足 | 给出D1/D2两份短原文、段落编号和A1–A3三条未判定回答；本人写审核后可打开教学对照，区分错误时间、无依据退款和有依据票据说明。无模型调用，也不判定技能通过 |
| 安全“异地”缺依据 | 统一为新设备信号；给出AUTH演练授权、ASSET资产/设备基准、E1–E3完整最小事件，不假设地点/IP或入侵根因 |
| 首屏结果太远、产物高低悬殊 | 压缩首屏介绍并合并返回/比较操作，同例结果小表在问题旁直接可见。数据产物改纵向工作页，表图并排，用途与验收归位；章节导航滚动时仍可用 |
| 比较像并排文章 | 六维使用同源的具体短句。完整范围/来源就近展开，详情继续保留全部工作解释；表头固定方向、移除可操作、2/3项同维比较及原目标预览保留 |
| 固定全站黄色下一步压过当前体验 | 职业方向、详情和普通比较不再固定显示“整理经历”底栏；当前体验、比较和目标动作在正文可达。我的机会/岗位等原业务流程保留 |

## 数据与后端

`careerLinks`保存在原材料JSON记录中，不新建账户表。新增确定性命令 `claim.link`，校验所有者、已确认状态、材料版本、确认动作、最多3职业、节点是否属于该职业；沿用原幂等回执和工作区并发检查。普通草稿同步不能修改关联。关联变动递增材料/画像版本，使相关派生依据需要重核，不直接写能力或完成记录。

`careerTrials`是当前账户的独立职业认知草稿，含案例版本和本人原文；最多10个方向、每份8000字符，前后端均验证范围和结构。不是经历候选、学习完成或技能检验，不自动进入AI资料范围。本人文字不随界面语言改写；清空只影响本例，删除个人资料仍按原清除规则处理。

公共内容版本为 `career-exploration-20261122-followup`，简明比较字段和最小案例输入仍在同一canonical内容模型，供详情、普通比较和既有AI投影复用。上一轮 `career-exploration-20261122` 和更早 `career-detail-20261024` 公共投影均留存；未知版本不回退成当前内容。已存讨论不改写，旧签名仍需重选依据。

本轮未新编外部职业事实，沿用上一轮已核来源及未读PDF边界；Power BI来源路径改为真实的preparation字段，英文业务数据分析改为business data analysis。仍须领域人员审稿，方法文档不代表所有国内岗位的统一日常与成长。
