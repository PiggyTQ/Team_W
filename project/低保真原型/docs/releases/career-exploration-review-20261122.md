# 职业探索与比较独立复核

2026-11-22。结论：**布局拆分、差异化案例和可见产物已基本落实；尚不能把学习承接、个人材料关联和阅读效果判为全部达到预期。** 建议在现有实现上定向完善，不推翻当前内容结构。

本轮是审阅，不修改网站业务代码、不部署。实现记录中的测试与截图作为历史证据另行阅读；以下结论结合当前源码、独立内容核对和本轮隔离浏览器检查。

## 已确认的进步

- 职业列表保留局部筛选，详情退出局部筛选列，全站导航保留。本轮1616桌面详情正文宽1338px。
- 10个方向已有不同任务、范围、判断、产物、使用者及协作。22份产物有实际表格、代码、图、记录或简报，关键示例默认可见。
- 603条数据的最新状态、重复、测试、撤回处理与SQL/前端结果一致；有效报名记录320→280，减少40、12.5%，没有转成独立人数或因果证明。
- 详情、普通比较、AI公共资料使用同一版本；原讨论不静默替换引用。公共信息与个人材料仍区分，未增加适合率或无依据市场统计。
- 保留原蓝黄暖白品牌。已查看的中英桌面没有正文横向溢出；小桌面允许两列产物，本身不属于还原错误。

## 需要修正的功能和内容问题

### P2 个人材料关联条件与正常录入链路不闭合

`src/career-exploration-model.js:21`只认已确认材料的`career===当前职业`或`skill`具有`data:`等内部命名空间。实际手动录入的SkillPicker使用SQL、Python等普通名称，experienceCandidate不带career；项目候选生成没有继承原任务career。用户通过正常界面确认一份SQL项目，仍可能在“有相关材料”中看不到任何方向，回个人评估录入也没有明确的职业关联操作。

定位：`src/SkillPicker.jsx:2`、`src/experience-writing-model.js:37`、`src/alignment-model.js:77`、`server/business-commands.mjs:169`及`:182`。

不建议退回“SQL=整个职业准备充分”。应提供可见、可保存、可撤回的相关职业/具体技能关联；有确切任务身份的候选可保留其来源映射。界面只称相关任务材料，不能提升为职业准备度。需用正常UI创建→确认→关联→职业页可见→解除的链路验收，不能只往测试夹具注入内部字段。

### P2 入门体验到技能练习的内容关系未解释清楚

本轮实际打开三个方向，链接均能到合法技能，但没有继续该职业页的小任务或材料：

| 职业页体验 | 点击后实际出现 |
| --- | --- |
| 报名CSV320→280、渠道变化简报 | 订单与退款的指标口径练习 |
| D1/D2须知、逐条审核回答依据 | 10例8例达标但1例泄漏受控信息的评测练习 |
| 优惠金额99.99/100/100.01 | 整数数量2至8的边界练习 |

这不是404，也不说明相关技能选择错误；问题是当前文案容易让用户以为将在下一页继续当前任务或检验同一份产物，实际已换材料。定位：`src/CareerReadingPage.jsx:28`；`src/content/career-exploration.json:179`、`:356`、`:1363`。

职业页应能独立提供完成小体验所需材料和产物记录方式；若下步只是学习相关方法，按钮和过渡应明确“学习相关技能，进入另一套练习”。若希望继续本例，则需明确携带案例身份、输入与草稿的承接，而不是只传skill。不要求为了此项重建整套课程。

### P2 AI体验与安全案例仍有材料缺口

AI案例只用一句话给D1§2签到时间、D2§1活动范围并宣布无退款条款；表格预先给出依据/预期和“错误猜测退款规则”“正确拒答”等判定，没有真实待审回答节选，却要求用户“为每条回答写支持段落”。现有信息可以理解示例，但不足以独立做引用审核。定位：`src/content/career-exploration.json:215`、`:253`、`:269`、`:344`。建议补短而可定位的原文与三条未预判回答，尝试后再对照。

安全问题写“异地成功”，E3只给“新设备成功登录”，没有地点/IP或基准支持“异地”。输入还称有资产清单和授权，但当前仅描述其存在。定位：同文件`:385`、`:386`、`:441`。应统一为新设备信号，或补实际合成位置字段；作为判断前提的输入给最小可查看内容。

### P2 新的筛选请求被旧返回状态覆盖

本轮浏览器可复现：访问`/careers?q=SQL`→打开数据分析详情→直接访问`/careers?q=Python`，最终被替换回`/careers?q=SQL`，输入框也变回SQL。

根因：`src/CareerBrowser.jsx:17–19`只要session记录`restore=true`便恢复旧URL，没有区分“明确返回原结果”和“用户主动发起新列表请求”。应只在返回场景恢复，显式新筛选参数优先；保留正常后退/返回的滚动与焦点恢复。现有导航单测没有覆盖这个冲突。

## 页面效果还需一次阅读层级整理

### 首屏未形成完整的案例认识

本轮1616×1100实际首屏，章节导航顶部约599px，产物区域顶部约1273px；首屏看得到职业标题、比较篮和案例描述，尚未看到概念图中让用户快速理解工作的数字小表与明确结果。

建议合并/压缩介绍、返回、比较等操作层级，把同一案例的结果小表或短简报预览靠近问题。不需要把所有正文塞进首屏，也不能用删掉具体内容来缩短页面。

### 产物卡高度差明显，长页失去定位

本轮数据分析三卡高度约656/988/648px，中间卡连续堆表、图、结果、下载、SQL、使用说明与验收，左右结束后留出明显空区。滚到产物时章节导航已完全离开可见区域。

建议保留核心预览，紧凑组织表图与结果，把次级操作归位；长页提供持续可用的章节定位或回到当前案例的方式。小桌面可纵向，但应保留交付链概览，不要求硬塞三列。

### 比较更像并排文章，核心差异尚不够易扫描

本轮选择器已收起，1616桌面比较表仍在约575px才开始首行“本页范围”；协作约1092px、准备约1273px、首个体验约1499px。长范围说明与多段产物内容使用户需要反复滚动才能比较。

建议主表保留同粒度的具体短句，长范围、产物细节和解释就近按需查看；始终知道当前对照的是哪些方向。完整职业内容继续留详情，不必把全部正文再次放进比较格。1366英文在收起选择器后本轮无横溢出，但无溢出不能代替可扫描性验收。

固定全站“下一步：整理我的经历”仍是明显黄色主行动，应评估它在职业探索中的优先级，避免盖过当前体验。未发现它使内容永久不可达，本项为产品层级建议，不当作实际遮挡故障。

## 来源与内容的审阅边界

抽查官方职业通知转载、SWEBOK、PostgreSQL、Airflow、SRE、PL-300与O*NET许可，未发现明显的版本错配；当前区分方法资料、原创建例和招聘事实的做法合理。方法文档能支持案例方法，不能单独证明全部职业日常/环境/成长具有普遍性，仍需职业领域审读。未抓取到全文的中文PDF继续保留待核状态。
