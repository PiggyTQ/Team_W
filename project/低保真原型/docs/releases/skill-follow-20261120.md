## 三条代表路径怎样教、怎样练

### SQL：先看重复，再理解关联规则

1. 两单U=90、V=40，总额130。U有10、20两条明细，V没有。点击订单可见U在输出中重复携带90，逐行相加变220。
2. 在观察后解释关联键、每行代表什么（粒度）、一对多、LEFT JOIN无匹配行及NULL；说明别名和ON的含义。先预测匹配次数，再归纳规则。
3. 用GROUP BY和SUM把明细压回每单一行；WITH为中间表命名。切换原始/修正查询，比较中间表、最终行及金额。解释为什么不能用金额DISTINCT替代按订单核对，为什么NULL不能无条件当0。
4. 对比ON内筛选与WHERE筛选：前者保留无合格匹配的V，后者会删除其NULL行。代码与输出紧邻，说明“过滤匹配候选”和“过滤连接结果”的差别。
5. 随堂行数预测只反馈示例，不长叶。练习换用A/B、D/E、K/L/M三套数据；最终检验另换记录，判断合适方法及无匹配行数。

练习现在可以实际运行查询。固定教学数据在本机Web Worker内用 **sql.js 1.17.0 / SQLite 3.54.1** 执行，输出表旁检查列名、订单键、每单一行、原金额、明细合计和NULL。原始左关联可执行却不能通过结果核对，错误反馈会指出重复粒度和明细合计，而非只显示“错误”。独立任务正确输出为K/50/20、L/50/NULL、M/20/5。

环境只包含当前两张合成表；单条SELECT/WITH，最多展示100行、续做保存前20行；5秒终止、16MiB SQLite堆上限。浏览器实测递归长查询会终止，等待期间输入的复核说明仍保留。它不是生产SQL接口，也不执行任意站内代码。PostgreSQL18原始资料支撑本课公共关联语义，不据此声称已实测全部数据库方言。

### 决策表：把漏掉的组合摆在眼前

从“会员或达到金额阈值免运费”开始：先改变会员与金额，看到当前组合/动作，再解释条件、动作、AND与OR。展开四种可行组合，区分“在某规则无关”与“不可行”，保留合并依据；用99/100/101比较端点。说明两个独立二值条件最多四组合，三个最多八组合，但要先判断可行性，不能把这当所有输入都覆盖。

三项练习分别使用100/8、60/5、80/6参数。用户逐行填写运费，再填写刚好达到阈值的动作。系统确定性检查这五项输入，指出具体错行及 `>=` / `>` 的问题；排错任务针对“会员并且达标才免”的错误方案。每个任务单独保留提示和复核状态。

最终检验仍沿用原有两项判断与一项书面应用；其中第一、第三项都涉及两个二值条件为四组合。本轮没有冒称已换成新的复杂迁移题库，结果准确写为“独立条件的组合数量、无关条件与可追踪合并、二值条件组合的书面计算”。日后若深化检验覆盖，应版本化题目和评分，不能悄然重评历史成绩。

### 事件交接：把证据、判断和未知分开

先展示H1超时、批准记录A7与执行记录R2等合成证据，逐条选择并对照其能支持、不能支持的结论：批准不代表执行，未检查的H2不能声明正常，也不能直接认定根因。再组织可继续接手的记录，解释UTC/Z、事实/未知、临时处置、批准/执行/恢复、责任与下次更新。

练习使用不同告警、日志编号和时间，分别编辑**确认事实、证据引用、仍未知、已做与待做、负责人、UTC更新时间**六个字段。排错任务重写“所有服务都故障了，已处理”的无依据记录。系统只检查字段、当前日志引用及有效UTC时间格式；例如 `99:99Z` 不合法。自由文字是否真实、根因是否成立、授权是否合理仍由材料对照和本人复核判断，界面明确说明这一边界。最终检验判断事实/假设、授权与执行条件，以及新增独立线索数。
