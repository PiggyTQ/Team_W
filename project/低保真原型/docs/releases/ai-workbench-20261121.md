# AI 工作台衔接：本地实施记录

> 发布状态更新：2026-11-21已按用户指示随[合并版本](combined-release-20261121.md)上线。下文“仅本地/未部署”与测试日期属于发布前历史记录，当前状态以合并回执为准。


## 实施前结构设计

沿用暖白、浅蓝、深蓝与黄色主操作。顶部只保留主题、历史、本人笔记与新讨论；上下文行依次展示意图、职业/比较对象、本次资料和模型状态。主体为单一讨论阅读面，结果紧接在相关问答下。资料与影响预览按需展开，不新增常驻三栏。

四类任务共用同一工作台。站内核对始终可用，模型单独校验全局授权和本次范围授权。成果仅写入待确认候选；计划预览对原任务作修改/延期，保留未选任务。检验继续由原学习页评分。

## 状态

本地实现与验证完成；未部署生产、未提交或推送 Git。原有未提交学习/成长树修改、账户库和费用账本保留。职业报告 V2 继续撤回。

## 已完成的链路

- 四类入口绑定讨论意图与资料对象，用户可纠正；取消旧六模式的假可用入口。任务与技能现场有「带着这一步继续讨论」，同对象复用讨论，保留原学习稿和返回位置。
- 本次资料按身份选择职业、技能/分支、分任务尝试、实际运行输出、复核、已公布成绩、综合项目步骤/产物、任务计划、目标预算、确认材料、复盘及报告/简历原文。最多12个引用，私密正文不进入URL。资料选择只授予站内使用；模型另要求既有外发同意与本次范围指纹确认。
- 撤回/修改/删除资料后，引用指纹、回答、笔记与预览失效。更换意图或对象后的旧消息合并为一个低频历史入口。仅发送必要近期六条问答，建议标为未确认数据，不转成可信事实或供应商系统角色。
- 计划预览修改或延期原任务，保留其他任务，展示预计投入、预算、依赖及截止日期变化。沿用原任务检查、工作区版本、事务和幂等回执，不以新增任务替代所有调整。
- 成果草稿从主动选择的原文整理，用户编辑后预览。确认只新增待确认材料；不创建完成记录、不自动确认经历、不授叶。回个人评估确认后，报告与简历继续使用原有确认材料链路。
- 规则核对使用当前技能节点身份；显式精确节点或节点名称可以关联，粗标签保持映射未知，不产生能力评分。
- 旧「自然语言检索」账户模式链接迁移到职业探索的岗位筛选，保存条件继续载入；站内工作台保留查找入口，不称关键词查询为整句理解。旧讨论、笔记、学习稿和计划保留。

## 本轮实际验证

- 相关 **98/98** 通过，包括新讨论契约、范围隔离、有限连续追问、取消/晚到响应、撤回、旧记录兼容、原技能成长规则、API鉴权及计划幂等。新文件 `tests/discussion-workflow.test.mjs` 有9项回归。
- 全量实跑 **529项：525通过、3失败、1跳过**。3项均为交接已记载的 `agent-budget-integration.test.mjs` 定价快照过期（`AI_BUDGET_PRICE_EXPIRED`）；本轮未改变该文件、定价策略或累计费用账本来制造通过。最后补充撤回断言后再次运行相关98项通过。
- 最终双语检查与 server 构建通过，原有大chunk/登录双重导入提示保留。差异检查无空白错误。
- 浏览器使用临时SQLite、隔离合成账户、关闭模型与邮件的本地HTTP服务，1700×1100中文与1366×960英文；页面错误数组为空，无横向溢出。不访问生产账户，不做手机验收。
- SQL：在原实践页真实运行SQLite查询→选择查询与实际输出→站内分层提示→返回同一稿修改→实际输出核对符合。之后通过原HTTP `skill.check`，先错误应用未过，再完整应用通过；未由聊天授叶。最终答题为受控合成测试输入，不冒称真人学习效果。
- 三小时：选两项原任务→2+2小时改成1.5+1.5小时并延后其中一项截止日期→查看影响→本人确认→任务ID和数量不变，预算为3，刷新恢复回执。幂等与版本冲突另经事务测试。
- 成果表达：选择产物及贡献→原文草稿→预览待确认候选→个人评估确认→报告预览包含确认材料。未伪造一个新完成行动。
- 项目助手：质量项目当前步骤和必要问答→同一工作台→返回同一步→再次进入仍同讨论。四项目复用同一组件和版本化步骤解析。
- 旧查询URL实际跳转到职业探索；旧搜索条件、讨论和笔记保留。历史/笔记管理沿用现有组件。
- 模型链路以注入可控供应商验证范围授权、六条近期上下文与晚到保护，**不是付费模型实测**，不对真实模型质量作结论。

## 保留的边界

- 外部模型与邮件保持关闭。真实供应商表达质量、真人使用及自由文本语义判断没有在本轮认证。
- 工作台预览任务投入、状态及截止日期；细化日历时段、周期目标及执行仍在原计划页面完成，不自动重排用户整周。
- 草稿和站内规则反馈不构成掌握证明。最终技能检验、本人材料确认与报告/简历编辑仍由原业务页承担。
