## 三页各自的资料和行为

### 梳理我的下一步

主线是“这次想解决什么 → 本次可投入的时间/约束 → 与此有关的目标和任务 → 聊天梳理 → 采纳一个可执行下一步”。避免要求用户先填写完整计划表。

- 从当前目标、相关原任务、可选复盘或技能反馈组织候选；显示任务中文名称、范围、状态、预计投入与截止日期。按关联对象选择，必要时再选择具体片段。
- **讨论中的目标或时间假设不是已保存的业务状态。** 用户输入“如果每周只有三小时”或临时选择另一个探索方向，只保存为本次讨论假设，不立即改 `state.budget`、真实目标或计划。界面区分“当前已保存”和“这次先按……讨论”。只有明确预览并本人确认后才能修改原业务。
- 不自动附上全计划、全部复盘或所有个人材料；未选记录不读取、不外发。
- 有原任务时，复用具体结构化建议到绑定草稿，跳到原计划页编辑、完整影响预览与确认，保留任务 ID、依赖和预算规则。
- 预算计算复用 `src/model.js` 的 `usedHours`：完成、跳过、取消、延期任务不计入当前分配，**只改截止日期不会释放预算**。方案若要把整理任务移出本轮，必须显式把该原任务设为“延期”，再经原计划影响预览和本人确认；不能从日期推断任务已延期。图 01 的合成示例可以是方案 A 两项各 1.5 小时，共 3 小时；方案 B 先做 SQL 2 小时、整理任务明确延期，而不是仅改 `due`。
- **没有原任务时，现有计划编辑草稿不能伪装成新增行动。** 不得捏造 taskId、复制原任务或绕过预检。当前范围优先提供讨论建议、存笔记及前往原学习/计划页创建行动的入口。若确需新增任务，必须另做与既有创建命令一致的显式预检链路，并清楚区分“新增”和“修改”。
- 空目标、无任务、时间未定、投入超预算、计划版本变化均有各自可继续的状态，未知不填零，预计投入不改写为实际耗时。

### 比较职业方向

主线是“选两个职业 → 对照工作与产物 → 说明本次关心的取舍 → 聊天追问 → 保存结论或去原页面采取行动”。两列对照可直接阅读，不以技能目录替代职业理解。

- 明确选择两个不同职业，双方名称和资料出处持续可见；交换、替换任一方后重新核对讨论依据和外发范围。
- **补充公共职业资料投影。** 当前 `server/agent/discussion-context.mjs` 的 `career` 来源主要是技能树分支/节点/lesson，不能直接据此声称已覆盖日常工作、工作环境和典型交付。复用现有 `src/model.js` 的职业 `task/env/output`，以及 `src/career-detail-content.js` 的 `lead/workflow/deliverables/collaboration/practice/source` 等真实已有内容，提供服务端可解析、带版本/内容指纹和来源元数据的公共比较资料；不要另写一份不一致的职业事实。
- 显示“平时在解决什么问题、如何做、留下什么产物、合作与环境、可先做的小尝试”。技能只作为其中一部分，必要时展开。
- 保留内容属性：职业资料是项目原创整理；练习为合成情境；O*NET 只用于已有职业功能参考，不挪用美国薪资/就业前景为国内结论，不声称经过独立职业专家认证。
- 不新增实时招聘、当前薪资排行、就业保证、适合度百分比、录用概率或未经验证的能力分数。不把职业基础泛化为所有岗位的统一门槛。
- 本人材料是可选补充，按需选择与本次比较相关的片段；没有材料仍可做公共工作内容比较，个人能力与偏好未知项应保持未知。
- 少选一方或一方无有效资料时，先补充选择/资料，不生成完整双向结论。材料因上下文限额被省略时，不能声称全面比较。
- 比较结果可存入现有笔记/讨论；“采纳为目标”去原职业/目标页明确确认，不能点击比较结果就悄悄改主目标。

### 整理成果表达

主线是“选一项作品或经历 → 选本次需要的产物/贡献/结果 → 补充表达用途 → 聊天整理 → 经历草稿 → 回原个人评估确认”。不得把整份档案当作默认附件。

- 以一项作品/经历为核心对象，用中文名称显示它属于课程练习、项目步骤、本人记录或已确认材料；保留其实际状态，不统一标为已完成。
- 产物、个人贡献、项目步骤、实际运行输出、复核说明是不同资料部件。选择“这一项作品”只定位对象，**不等于全部 part 获准外发**；展示具体使用的部件及必要范围。
- 页面使用“产物原文”“本人贡献”“实际结果”“复核说明”“当前步骤”等中文名称；底层继续保留 `kind/id/part/stamp` 和真实对象身份，不在界面铺英文内部枚举，也不以中文显示文本替代稳定身份。
- 可以补充“准备口述/面试/简历”等表达用途或一段本人说明，但这些是**未核对的本次说明**，不是新的确认材料。不可自动给用户编造贡献、指标、角色、影响、完成状态或经历真实性。
- 若本次说明将参与生成、外发或草稿来源，应以明确的临时自述类型记录并进入范围摘要、指纹和变更失效机制；不能塞入不受校验的隐藏提示词，不能仅改 UI 文案便声称后端已支持新类型。
- 原文与拟表达尽量可对照；结果未知、贡献未说明或证据矛盾时先追问，不能用泛化的成果句补空白。
- 从具体结构化建议生成来源绑定的可编辑候选稿；没有结构化建议则只能显式手动起草，不从自由文字猜业务命令。回原个人评估页编辑、预览、确认后仍为待本人逐项确认的材料，后续报告/简历接纳遵循原链路，不直接改写既有输出。

## 跨任务会话与恢复

不能继续在同一讨论上切换 intent 来冒充独立任务页。

- 三页分别定位或建立其任务讨论，保存各自未发送问题、选中对象、假设/用途、已授权范围、消息及草稿引用。任务切换不覆盖另一页状态；自由聊天和 Tutor 会话同样保留。
- 复用原账户存储，不另建账户数据库或用全局浏览器键混放不同账户的草稿。对现有会话模型作兼容扩展，保留旧数据，不批量伪造或迁移成新事实。
- 现有 `startDiscussion` 按意图、职业与引用对象匹配；新增路由状态时必须检查复用条件，避免把不同作品、比较组合或独立问题强行合并，也避免每次返回都建一个新讨论。

- 刷新、后退、跨页、关闭/重开 Tutor、不同语言切换、账户退出重登均保留原有合法恢复行为；未经确认的改变不得因恢复而被自动应用。
