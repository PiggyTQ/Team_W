# 职业探索与比较的内容及界面改进

推荐将职业探索分成“发现方向”和“读懂一个方向”两种阅读场景。列表继续提供筛选；具体职业说明使用完整内容区，以一条具体案例展示工作及产物。内容深度优先于卡片数量，不靠增加标签页、折叠项或提示语制造完整感。

## 页面如何重新组织

列表页保留局部筛选与比较篮，卡片继续用于发现方向。每张卡片清楚说明“关注什么问题、常见产物、一个代表工作”，减少对所有卡片重复的装饰和泛化提示。无需为了统一详情而删除列表筛选。

打开详情时，局部筛选及其空列、相关筛选浮层入口一起退出布局；全站左侧导航保留。返回筛选结果、收藏、加入比较、查看已选比较仍能找到。返回时恢复搜索、候选来源、分组、滚动和原卡片焦点；直接进入详情也有合理默认返回。

详情首屏先回答“做什么、交付什么、与谁协作”。职业名称下用具体句子说明工作对象、行动与目的。标题区压缩普通保存状态和装饰高度，主要内容不被大横幅推到首屏之外。

正文围绕五个阅读目标组织：工作与案例、能力与准备、成长与协作、入门体验、来源与范围。效果图用五个入口示意，但实现可以根据内容合并、锚点导航或分节；不要为了凑满入口重复同一说明。主要工作说明及重要实例默认可见，许可全文、来源版本等低频信息按需查看。

正文以舒适行长为约束，案例表格、流程、产物预览可用更宽区域。移走筛选栏后不将普通段落拉成一整屏长行，也不新增常驻空侧栏。建议普通正文约35–50个汉字一行，实际按字号与可用宽度调整；小桌面产物卡可改为两列或纵向，不能压成不可读缩略图。

保留当前暖白背景、深蓝文字、浅蓝辅助面、黄色主操作、薄暖灰边框、圆角和现有角色。角色承担引导即可，不能占去解释工作所需空间。不要重画品牌、改成深色系统或将所有信息包进多层卡片。主要内容依靠文字层级、留白和少量适当的表格建立结构。

## 以数据分析示范所需内容深度

一个案例持续贯穿问题、处理和结果，统一标明本站原创合成示例。案例用于认识一类任务，不是所有公司工作的统一规范。

情境：活动负责人发现5月报名比4月少，想知道变化集中在哪个渠道、下一步应核对什么。分析师先约定按registration_id去重、排除测试和撤回记录；统计单位是有效报名记录数，不是独立人数。月份只作教学示例。

| 渠道 | 4月 | 5月 | 变化 |
| --- | ---: | ---: | ---: |
| 官网 | 160 | 120 | -40 |
| 社群 | 100 | 100 | 0 |
| 短视频 | 60 | 60 | 0 |
| 合计 | 320 | 280 | -40 |

发现是总数减少40条、降幅12.5%，现有分组变化来自官网渠道。没有访问量、转化率、活动变更及采集检查，不能断言用户兴趣下降、投放失败或系统故障。下一步核对官网入口与采集，再决定是否需要更深入的转化分析。

这条案例产生三份看得见的东西，而不是三个文档名称：

1. 指标口径卡：统计对象、去重键、时间范围、排除条件、字段来源及待确认项。使用者是业务/产品，目的是先对齐问题；验收时看同一条件能否算出同一结果。
2. 分析表与图：展示真实可核对的小表、计算方式、SQL或表格片段、合计对账和恰当图形。使用者是业务和复核同事；验收时检查统计单位、处理规则、图表和总数一致。
3. 结论简报：直接给一段“发现—证据—限制—下一步”样稿。使用者是活动负责人；验收时检查事实与推测分开、行动与证据对应。

每份产物的关键预览直接可见，附“交给谁、解决什么问题、如何检查”。完整说明、放大预览或原创文件下载可按需打开；没有真实资源就不放假下载。三份产物与前面的同一问题互相引用，不另起不相干的案例。

能力说明要解释如何影响产物质量：SQL用于取数与聚合核对，指标定义用于避免统计对象不一致，沟通用于澄清问题与解释限制。基础、核心、进阶用于组织学习，不是全公司统一门槛。已有一份SQL材料只能说与某类任务有关，不能变成完整职业准备度或适合率。

成长用任务自主程度、复杂性与可观察产物质量说明；协作写明接收/交出什么、怎样处理口径争议，而非只列角色。入门体验让用户用一份有字段说明的原创数据，交出小型口径卡、分组结果和简短判断，并明确到完整学习/实践的去向。职业体验不替代技能课程，更不能凭看完示例标记技能掌握。

## 其余方向如何补齐

下列是待研究和编写的案例方向，不是本轮已完成的职业百科或得到专家确认的企业规范。为每个方向独立核对一手职业及技术资料后再编写，数量随信息需要，不能固定每个方向都三卡四步。

| 方向 | 可研究的代表任务 | 应看见的原创产物示例 |
| --- | --- | --- |
| 数据分析 | 解释某指标变化并核对口径 | 指标卡、分析片段、结论简报 |
| 人工智能 | 先区分应用、算法、平台，再选择一个任务 | 任务边界、测试问题、评估与错误分析；问答应用只是一个细分案例 |
| 网络安全 | 在授权的合成日志中分析可疑行为 | 事件时间线、证据与不确定性、处置建议；不引导未授权测试 |
| 运维工程 | 服务异常下判断影响并计划恢复 | 用户影响说明、监测/告警规则、恢复和复盘记录；运维/DevOps/SRE应说明范围差异 |
| 前端开发 | 实现可交互表单与错误状态 | 可操作界面、响应式及键盘检查、组件说明 |
| 后端开发 | 设计一个带校验和权限的业务接口 | 请求响应样例、错误/权限矩阵、接口测试记录 |
| 数据工程 | 多源数据按约定稳定进入下游 | 数据契约、转换/调度示意、质量检查和故障处理 |
| 软件测试 | 为一个具体功能发现并复现缺陷 | 风险与测试设计、复现报告、回归依据 |
| 通用软件开发 | 从需求到可维护功能的完整交付 | 需求约定、实现/测试、评审和运行说明；与前后端展示交叉关系 |
| IT实施交付 | 将某方案配置、迁移并交接给使用方 | 配置/迁移检查、验收证据、交接与培训资料 |

十个基础方向不是十个互斥的标准职业，英文名、职业代码与国内称呼也不总是一对一。方向页先说明范围及细分；具体案例标明代表范围。不要为了“全面”拼接与所述岗位不符的学历、证书、薪资与任务。

## 比较页和后续链路

将详情、普通比较和AI公共职业资料整理为同一内容来源，按关注问题、常见活动、产物、协作、基础及首个体验任务比较2–3个同范围方向。不以三个职业短句或大段空泛性格词代替对照。不同层级比较时明确标明细分范围，图中的人工智能应用是示例子方向。

保留收藏、比较、选为目标三种行为的差异。比较不自动改变主目标；目标仍经过既有预览/确认。原技能树、课程、实践、本人材料与计划继续复用，不另建体系。公共内容进入AI不附带整个账户；本人材料按现有选择和授权加入。更新职业内容时保留内容版本，旧讨论引用不能被悄悄改成新内容。

## 可行性与实施顺序

| 工作 | 可行性与主要成本 |
| --- | --- |
| 详情退出局部筛选布局，重排标题/正文 | 较低开发复杂度；需检查旧样式的父级选择器、深链接、返回与比较入口 |
| 增加可见案例、产物预览与使用说明 | 现有React页面可扩展，无需换技术栈；原创内容与资料核对是主要工作量 |
| 三处职业信息同源及版本映射 | 中等；可基于现有career-comparison公共投影，避免向公共数据混入个人材料 |
| 全部方向逐项研究、来源/许可记录 | 持续编辑工作；本轮仅充分核对数据分析样例参考，其他方向仍需独立研究与一致性检查 |
| 新增薪资、趋势或适配评分 | 不是本次必要项；没有地域/时期/样本/合法使用依据时不能编造 |

先做数据分析完整纵向样板，同时整理全部方向的内容缺口和来源计划；验证结构后将差异化内容覆盖全部现有方向，再统一比较与英文。不要用样板完成代替全范围完成，也不要先铺满十份泛化模板再声称内容已完善。技术验收可以本地完成，职业领域审稿、真人理解效果与招聘市场真实性需分别验证。

## 验收重点

- 列表保留筛选；详情没有局部筛选或空列；返回/刷新/后退及原卡片焦点正确。非法职业/章节和无来源详情有清楚回退。
- 收藏、加入/移除比较、打开比较、比较满3项反馈和原目标确认正常；相关入口不因移走筛选而失踪。
- 1366与1616以上桌面，中英文、长标题、长内容、2/3职业比较无横向溢出或遮挡；键盘焦点、标题和表格语义可用。扩展小屏时自行核对，不冒称本轮已验收。
- 不展开额外折叠就能说明该职业做什么，看到至少一个可理解的工作案例和有内容的产物；十方向职责及示例有实质差异。
- 示例数据、图、代码片段和结论一致；用确定检查验证计算与链接，不做只照抄实现的测试。
- 逐条来源能支持相应主张，原文日期与本站核对日期分开；许可不明确的素材不直接再分发。个人状态、公共案例和真实招聘事实清楚区分。
- 实施前重新核对工作区与项目交接，保留他人修改。完成后保存实际浏览器截图与测试结果，概念图不算上线或验收。
