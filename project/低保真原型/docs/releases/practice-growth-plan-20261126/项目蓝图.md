# 十职业项目蓝图

下表是本站拟原创的任务范围，不代表同名外部课程、已取得的素材授权或已完成的内容包。每项发布前需按项目规范备齐材料、来源、参考、验收与维护责任。三个层次关注任务复杂性和自主程度，不对应企业职级。

现有4项纳入第一列，其余均为拟新增。角色不同或换一份数据不自动计为独立项目。

| 方向 | 入门：交出小成果 | 进阶：增加约束与判断 | 独立综合：交付可接手结果 |
| --- | --- | --- | --- |
| 数据分析 | 数据质量与口径复核（保留现有项目）：问题清单、处理依据和可复算统计 | 多来源业务分析：关联关系、分组比较、图表及限制，防止重复计数 | 指标/数据版本变化下的分析交付：复算、变更影响、报告与使用说明 |
| 人工智能 | 客服助手评测（保留）：逐条依据、错误与评估边界 | 从简单基线到独立评估：切分、标签/信息泄漏、指标复算与错误切片；可选传统小模型 | 受限知识助手交付：资料权限、引用/拒答、评估集、失败与成本记录、维护方案；离线/真实调用分别标明 |
| 网络安全 | 离线日志初筛（保留）：时间线、替代解释和升级依据 | 隔离应用中的权限问题与整改复验：有界复现、影响、修复与回归证据 | 检测与响应交接：正常/异常混合记录、检测查询、误漏报分析、授权处置建议及复盘 |
| 运维工程 | 故障恢复与回退（保留）：恢复条件、停止条件与复验 | 告警规则与反例：时序输入、规则、持续时间及正常/缺失/恢复测试 | 服务上线与可靠性演练：配置、遥测、故障假设、恢复与业务验收；本地环境或固定证据包 |
| 前端开发 | 可访问的表单与状态恢复：可操作界面、键盘/错误/等待与失败检查 | 数据工作台：筛选、分页、空状态、接口失败、组件及自动回归 | 小型业务界面交付：多页面、接口契约、兼容/性能、测试与变更说明 |
| 后端开发 | 有校验和权限的业务API：请求响应、数据模型、错误/动作矩阵和测试 | 预约/库存的一致性：重复请求、并发占用、事务失败与恢复 | 可演进的服务：接口兼容、数据迁移、诊断信息、回归与交接；按给定隔离环境验证 |
| 数据工程 | 从原始表到可复算模型：粒度、清洗/关联、字段字典与质量测试 | 固定分区重跑与发布：内容一致、迟到数据、失败阻断和发布机制 | 数据交付演进：上游结构变化、血缘、下游契约、回填和运行维护 |
| 软件测试 | 从需求到可复现缺陷：边界/状态、预期、观察和复现证据 | 接口与界面回归：埋入缺陷、测试数据、自动检查和修改后确认 | 发布风险评估：风险优先、环境和版本、执行结果、未测范围及剩余风险交接 |
| 通用软件开发 | 小型规则/转换工具：需求约定、程序、边界与错误检查 | 遗留代码维护：需求变化、测试保护、重构、兼容与评审记录 | 可发布工具包：接口、配置、文档、版本、持续验证与接手运行说明 |

## 六个跨职业综合情境

这些情境在核心项目稳定后制作；应有独立任务目标和跨角色验收，不能将同一项目复制六次换标签。可以沿用材料世界和部分成果，变化在接口依赖、责任分工与共同验收。

| 情境 | 相关方向 | 真正需要交接的内容 |
| --- | --- | --- |
| 活动报名服务 | 前端、后端、测试、实施、软件开发 | 需求与状态→接口→实现→权限/异常验证→业务验收与交接 |
| 指标与数据服务 | 数据分析、数据工程、后端、测试 | 数据契约→可用模型→分析报告→对账与刷新说明，字段变更共同处理 |
| 受限知识助手 | AI、数据工程、后端、安全、测试 | 资料/权限→服务契约→问答评估→边界测试→发布与运行限制 |
| 服务发布与故障演练 | 运维、后端、前端、测试 | 变更→遥测→用户影响→恢复→业务复验与复盘 |
| 应用安全整改 | 安全、后端、前端、测试 | 授权范围→问题证据→整改→回归→剩余风险确认 |
| 业务系统迁移上线 | 实施、数据工程、运维、测试、数据分析 | 映射/冻结→迁移对账→权限/UAT→切换/回退→培训与支持 |

每个情境可以先提供单人角色轮换。使用预制交接件时说明其为教学素材；AI模拟他人意见时标明模拟。多人共同编辑、任务分工、审阅和责任身份没有实现前，不以“团队实战”宣传。

## 实际验收方式按产物分类

| 产物 | 能确定性检查的部分 | 仍需量规或复核的部分 |
| --- | --- | --- |
| 数据/SQL/分析结果 | 字段、主键、连接基数、汇总、参考结果复算、内容差异 | 指标是否回答问题、处理理由、推断范围、表达质量 |
| 代码/API | 指定测试、错误/权限契约、输入输出、重复效果与迁移检查 | 方案取舍、可维护性、未覆盖风险；测试本身是否充分 |
| 界面 | 指定流程、键盘路径、状态和部分可访问性/布局检查 | 易用性、内容理解、真实辅助技术体验 |
| 配置/告警 | 规则语法、固定时序下的触发、数值、标签和恢复测试 | 是否符合真实服务目标、误报成本与运行判断 |
| 安全分析 | 字段解析、事件引用、指定查询命中/漏检与复现实验 | 归因、影响、授权和处置取舍 |
| 实施/交接文档 | 清单完整、字段对账、证据链接、已知验收结果 | 用户能否按它接手、业务适用性、培训/支持与责任清楚程度 |

验收状态要说明检查了什么。没有真实执行环境时，不伪造日志或“自动验证通过”；结构完整、本人复核与独立验证分开。
