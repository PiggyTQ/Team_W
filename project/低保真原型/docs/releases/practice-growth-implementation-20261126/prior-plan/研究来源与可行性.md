## 现有数据质量项目的来源应怎样解释

[GDS案例原文](https://www.gov.uk/government/publications/the-government-data-quality-framework/the-government-data-quality-framework-case-studies#government-digital-service-improving-pipeline-data-quality)真实存在，讲政府数字/技术支出报送的质量改进，没有提供可直接评分的支出原始表和标准答案。本站练习已明确改用DfT碰撞数据并注入教学问题；这不是虚构GDS案例，需改善卡片的来源身份说明。

[政府数据质量框架](https://www.gov.uk/government/publications/the-government-data-quality-framework/the-government-data-quality-framework-guidance)可支撑目的适用性、质量规则与持续改进，不独自证明本站分析结论或评分正确。框架及案例页声明OGL v3，第三方内容除外；采用时按[OGL条款](https://www.nationalarchives.gov.uk/doc/open-government-licence/version/3/)核对归属和实际材料范围，不用“政府出品”替代本站设计责任。

## 工程现状和必须先处理的扩容限制

本轮静态核对和Node24只读内存计算：`src/model.js`和`course-packs/practice-20261113/catalog-ready.json`均四项目，四课各四章节，共16章节及21来源条目；没有把来源条目或123技能节点当综合项目。`LearningCentre.jsx:14–26`按主目标默认筛选，导致数据方向仅一项。

可复用：原项目概览/阅读/四步实践/成果、成员/主理人视角、预算与依赖、版本化阅读/尝试、我的资源及材料确认。当前角色是个人视角，不是多人协作。正常材料关联已经修复，不能再按旧问题重建。

需要规划改造：

1. **目录与迁移。** `practice-project-model.js:1`、`PracticeProjectPage.jsx`、演示清单与`server/course-library.mjs:9/55–57`固定四ID；导入要求恰四课、四章节、一视频，数据库课程预先存在。改为可独立加入项目、对老账户安全可重复迁移，仍校验身份和材料，不简单删保护。
2. **独立版本。** `course-library.mjs:53/82–83`把整包manifest摘要用于每课，一个项目变更会影响其他版本。应采用每项目版本自己的材料摘要及发布批次，继续不可变与完整性校验，不能通过放松hash判断绕过冲突。
3. **多种产物。** `practice-project-schema.js`当前证据表≤150行/10列、说明≤1200字、固定四步。保留旧类型，增加与项目相符的数据、代码、接口、配置和文档产物；完整材料包独立于小预览。
4. **评价边界。** 当前`projectPracticeReady`检查选择/证据/非空说明；可接受已登记但不合理的选择组合，只说明结构完整，后续本人自检。语义、代码和计算未由综合项目统一独立验证。新执行能力与可信评分需要实际建设，不能改界面标签便称已有。
5. **退役与历史。** `course-library.mjs:120`读取材料后硬返回published，而后台可retired、创建校验又保留该状态。静态路径提示目录和允许新开可能不一致，本轮未用数据库复现；设计需分开“允许新开”和“历史可读”。
6. **内容后台。** 现有管理有编辑/审阅/发布和审计可用，综合项目仍主要CLI导入；新增素材候选、编写/试学/来源更新和发布流程，不另建账户体系。

本轮没有网站构建、业务测试或生产操作，历史验收不能转为本轮实测。任意代码沙箱、真实外部集成、实时多人协作和独立评分是高成本新增能力，可晚于第一批有明确产物和复核的项目。
