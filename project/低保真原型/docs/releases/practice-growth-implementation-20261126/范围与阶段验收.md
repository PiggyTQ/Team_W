# 完整范围与阶段验收

本文件供未来实施使用。本轮交接包不含已完成教材或运行结果。

## 数量及身份

- 共36个独立项目：10职业各3个核心项目，共30；6个跨职业任务。
- 保留quality、ai-eval、log、restore及全部历史版本，其他32项新增。
- project-briefs.json的ID是规划稳定身份。发现与现有注册信息冲突时记录映射理由，不能静默复用别的项目ID。
- 角色、同题重做、难度标签、变式、链接不作为独立新增项目。相邻项目复用资料和骨架可以，但业务判断、产物或检查需有实质增量。
- recommendedPriorProject是建议基础，不必变为强制锁课；用户有相应经验时可选择其他路线。

## 四个中间验收点

| 验收点 | 必须完成的结果 | 不能作为完成依据 |
| --- | --- | --- |
| 基础与10项目 | 项目注册/独立版本/增量迁移可用，保留4项并新增6职业入门；服务模式和演示模式一致 | 仅首页出现10卡、数据库重新初始化、旧任务无法读 |
| 20项目 | 十方向各有进阶，实际材料、产物、检查及后续路径接通；适配不同产物 | 同故事改名、只加阅读材料、把所有项目降为同一填表 |
| 30项目 | 十方向各有独立综合交付，新情境/输入及较少脚手架，可保存、验证、归档和导出 | 公开示例逐项换数字仍称独立迁移 |
| 36项目 | 六个跨职业交接跑通，并完成持续内容流程与受控变式实证 | 只添加职业标签、只写角色名称、AI模拟当真人合作 |

以上是实施顺序，完整目标仍是36项。若客观外部条件暂不可得，继续其他独立工作并明确受影响项目、替代办法和缺失证据；不能悄悄缩成10项完成，也不能降低来源门槛。

## 完成与发布状态

| 维度 | 完成要求 |
| --- | --- |
| 内容制作 | 实际任务正文、原始/合成输入、数据字典/契约、可下载包、产物要求、提示、参考/量规及限制均存在 |
| 技术复现 | 实际文件解析、参考复算或执行、正确/错误/缺项场景，以及对应产物完整流程有记录 |
| 来源与权利 | 所用材料的归属、版本、许可适用文件和改动可追溯；待核不能改已核 |
| 内容审阅 | 记录实际检查范围/方式/执行者；AI辅助检查不冒称独立领域人员签署 |
| 真人试学 | 有真实试做才能写通过，无条件时保持未做并给具体计划，不编造用时、评分或学生反馈 |
| 正式发布 | 按采用的治理条件逐项满足。新增项目可先本地试用；不得为了36数量批量置published |

本地可试用项目必须能真正开始、制作和交付，不能将缺输入、无参考或损坏下载藏在待试学标签下。来源或材料确实不合格时不能称本地完整，必须标明未完成并尝试合法完整替代。

## 最终36行验收矩阵

实施者输出可读表和机器记录，每行至少有：

projectId、内容版本、主/相关职业、具体技能映射、材料包和manifest路径、许可状态、字典/环境、产物入口/格式、检查种类/版本、实际参考验证、代表失败用例、正常/修改重评证据、下一步项目ID、旧版本策略、内容审阅、真人试学、发布状态、明确待办。

技术验证记录要关联工具版本、输入及产物摘要、实际时间与日志。参考验证和学习者提交验证分别记；提交修改后旧评价过期；外部平台练习的访问不计本站掌握。阶段截图、卡片数量、构建成功、字段非空和来源条数不能替代矩阵。
