# 页面与用户链路的具体效果

本文件定义未来应呈现的效果，不是新UI截图；prior-plan/reference为用户现状图，不当作实施后的页面。

## 资源中心

首屏能找到“继续我的任务”“当前方向的递进路线”和“查看全部方向”，避免用户看到一项就认为库中只有一项。当前筛选数量与全部正式/试用数量分开；草稿不能混进正式项目数。

按方向、家族与层次组织，不一次展示36张巨型卡。筛选先围绕目标能力、层次、投入、成果及环境条件，低频字段按需展开。十方向都可发现；当前目标无结果时说明原因和替代，不从下拉隐藏空缺方向。选择其他项目不自动改主目标。

卡片首先回答做什么、形成什么、此次新增什么能力；同时有建议基础、投入估算、账号/环境/费用条件、来源简要身份和可读状态。用时未经试学就标编辑估算，不当承诺时限。已在做的项目突出续做，不用新版本覆盖旧任务。

## 项目概览及实践

进入概览看到具体问题、输入预览、可取得材料、约束、产物样式、验证方式和限制，再按原预算安排。真实文件链接与版本清楚，未下载/未运行状态不伪装已检查。

不同项目使用合适编辑和产物空间：数据/SQL、代码/API、界面、配置规则、测试、交接各有对应制作和保存方式。页面结构可共用，任务操作应体现差异。长学习与实践使用专注独立页面；成长树在选路或总结时出现，保留原技能检验去向。

提示分层，给定位、方法和反例。独立任务减少逐步提示；看过完整示范后不把同题重做当未见题迁移。AI建议与真实检查可见区分，引用指向所选版本，不读全账户或私自发送产物。

## 完成页

先呈现本次产物、版本、本人贡献、实际检查项和剩余问题，再给两三个明确后续入口：

1. 补强具体缺口：进入对应产物位置，修改后旧结果过期并可重评。
2. 挑战新约束：说明增加的条件，哪些原成果可沿用。
3. 换情境独立完成：说明新输入和提示范围及拟观察能力。

已有成熟成果也可进入跨职业交接。推荐理由来自用户选择、任务记录、已验证范围和预算，不由浏览时长/求助次数推断人格或能力。允许暂停、跳过或改选，不自动填入计划、不把简单点击记录成掌握。

## 六个跨职业情境

显示当前角色接收什么、产出什么、交给谁、对方如何提出反馈，以及修改后怎样复验。单人轮换与预制交接件标教学模拟，AI生成的意见标AI模拟；不宣传真实团队合作。角色贡献和共享资料范围清楚，不能在一份通用报告里写完角色名称就算交接完成。

## 来源与状态

区分“本站设计”“实际材料发布者”“案例参考”“方法依据”。quality卡片宜明确GDS为支出报送案例参考、DfT为交通数据来源，而非GDS出品交通项目。完整署名、许可、改动和复核信息可展开，但必要适用范围就近显示。

未发布、试用、正式、需复核、退役与旧版本可读有明确含义。普通用户不必面对工程字段和冗长审计；遇到材料失效、保存冲突、运行失败或版本变化，说明影响和可采取动作，原稿保留，不显示虚假成功。

沿用现有品牌、字号/颜色与导航。正文、代码和表格可读，操作位置稳定，长内容有定位。当前章节、键盘焦点、空状态、保存/失败与输入法行为实际验证；不靠缩小所有文字容纳更多项目。
