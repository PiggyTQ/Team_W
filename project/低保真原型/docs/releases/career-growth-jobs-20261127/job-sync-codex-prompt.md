# 后续岗位同步实施提示词（国内企业官网与校招优先）

请在当前实际工程上实现岗位来源同步。先读根交接、适用AGENTS、README、本目录`job-sync-domestic-research.md`及本轮发布说明，保留共享工作区已有修改。目标是持续更新一批可信国内企业/校招岗位，并让用户看见来源变化；不要把合成示例或历史采集时间改名为实时。

## 当前事实与目标效果

本机演示是2条原创合成岗位；账户页`CatalogJobs`从`/api/catalog/jobs`读取知识库历史快照。`server/knowledge-store.mjs`是只读知识库，返回的demoOnly、scope和日期语义均针对历史样本；它不是实时招聘服务。个人研究卡已有catalogId/catalogVersion/sourceSnapshot，笔记、任务和求职事件各自保留。

页面已有腾讯、华为、百度、字节跳动官方校招入口导航。导航核对日期不是岗位更新时间，入口可访问也不等于获得批量读取或转载授权。按来源能力分开显示“官网查找”“已同步职位”“历史研究样本”，不能混成一个看似实时的列表。

## 先交付一个真实来源闭环

只连接明确获得授权并确认可对外展示的企业ATS/feed。飞书或Moka可作为企业范围适配器候选，不把企业侧接口当全网招聘检索。根目录、企业/租户、字段范围、鉴权、限额和数据保留规则须以当前提供方文档与实际配置为准；缺少凭证的来源保持未连接，不生成成功时间或虚拟岗位填充空态。凭证仅在服务器配置，不进入仓库或浏览器。

建议新建独立`server/job-feeds`服务与数据存储，保留旧知识库查询及身份。不得直接把旧历史库的`demoOnly`或`postingStatus`覆盖成新状态。先完成一个获授权企业，再扩展企业清单；来源变更推送只有在供应商明确支持岗位事件时才做，其他情况用增量轮询和完整对账。

## 具体行为

1. 来源登记包含官方域名、企业/租户、允许展示的字段、授权/审核依据、同步方式、负责人、关闭开关和刷新约定。来源域名及API入口由后台配置，不能将用户填写的任意岗位网址直接当服务器抓取入口。
2. 岗位稳定键由来源+租户/企业+外部职位ID组成。保留原文或获准摘要、官方链接、原始发布状态、来源发布时间/更新时间、本站成功获取时间、版本哈希。没有的日期和薪酬保持未知，不由AI补造。
3. 每次增量同步先完整分页再提交版本；失败保留上次成功版本并显示失败/过期，不推进成功时间或游标。日常完整对账弥补增量漏项。一次超时、空页或增量里未出现，不直接判为岗位关闭。
4. 定时更新采用供应商允许的频率。15–60分钟只能作为试点评估范围，实际按限额与变更量决定，未验收前不宣传秒级实时。用户刷新只读本站缓存，避免每个用户直接请求供应商。
5. “我的机会”固定用户保存时版本。来源职责/地点/薪酬发生变化后，显示具体差异和最近成功核对时间；本人选择是否采纳新来源版本。保留旧原文、笔记、准备任务、材料和申请/面试事件，更新来源不自动写入投递、面试、拒绝或完成状态。
6. 老catalogId/catalogVersion/本机合成卡和手动私有卡继续可读。新引用要能区分历史目录与同步来源，必要时扩充明确的类型字段和迁移测试，不改变旧字段含义。手动卡未有稳定来源ID时，只提供原站核对和手动更新。
7. 从官网跳转申请时保留原站处理流程，本站不自动投递简历、同步招聘账号、处理候选人/面试数据；此类能力需另外有本人授权与相应企业接口。

## 验收

- 用隔离夹具覆盖新增、相同内容不重复、修改、明确下线、分页中断、空增量、全量异常、429/超时、凭证失效、重试去重及停止来源。
- 一次失败不得刷新“最近成功同步”，不得批量关闭岗位；只有明确来源状态或验收过的完整对账策略才改变下线状态。
- 个人研究卡差异可见；采纳前后原稿可查，笔记、任务、事件完整保留；旧卡与本机模式回归。
- 实测来源身份与显示范围过滤，内部/未发布/不允许展示职位不进入公开结果；原始HTML不得直接无过滤注入页面。
- 中英文、1366/1616/2560以及窄内容容器检查，岗位名/正文/元信息保持本轮字号层级。
- 区分“夹具测试通过”与“真实来源联调通过”；实际联调才记录源的最新成功时间、覆盖企业和刷新周期。保持现有关闭入口，默认不部署生产。

完成前更新来源登记、真实联调回执、设计与实际截图以及共享交接。无可用授权配置时，完成可审阅代码和夹具验证，明确唯一缺失项，不能把实现框架冒称已取得真实岗位数据。
