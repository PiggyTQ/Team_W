# 国内企业官网与校招优先：岗位同步可行方案

核对日期：2026-11-27。本文是研究与待实施方案，没有接入新的实时数据源，没有调用付费接口、企业凭证、招聘平台登录态或修改线上岗位库。接口能力、商业开通条件和对外展示范围最终以数据提供方确认及实际租户验收为准。

## 推荐结论

适合本站的路径是：**官方企业/校招入口导航 → 用户主动保存研究卡 → 少量获得授权的企业岗位源增量同步 → 来源变更提示与本人快照对照**。

先把“覆盖中国全部招聘网站”缩成“持续维护一批可信、适合目标职业的国内企业/校招来源”。每个来源显示实际覆盖的企业、来源地址、上次成功同步和更新方式。没有获准使用的数据源保留官网入口，不让合成示例承担“当前岗位”的角色。

“同步岗位资料”与“自动同步投递/面试进度”必须分开。前者可以由获授权的公开岗位源实现；后者涉及本人在招聘系统中的申请记录，当前没有可用授权链路，仍由本人记录。职位变更不能自动记为本人申请、拒绝或面试。

## 当前代码事实

- `src/JobDiscovery.jsx` 按 `SERVER_AUTH` 分流：本机演示只有两条明确标识的合成岗位，不代表在招。
- `src/CatalogJobs.jsx` 的账户模式从 `/api/catalog/jobs` 查询知识库历史岗位快照。`server/knowledge-store.mjs` 提供该查询；页面明确显示历史、采集日期与未核验状态，当前不是实时招聘聚合。
- 加入“我的机会”时保存 `catalogId`、`catalogVersion` 和 `sourceSnapshot`。这些字段可以承接未来的版本差异；私人笔记、准备任务与求职事件仍须独立保存。
- 当前 `ExternalJobLinks` 只提供BOSS官网导航；它没有将账户、私人材料或查询自动发送到招聘网站。不能因为增加官网链接或点击“刷新”就把状态改成“实时”。

## 无凭证时现在可以做的事情

国内企业官网与校招入口可以作为人工查找导航。入口导航不意味着已经批量读取岗位或获得内容转载范围：

| 官方入口 | 本轮观察与页面处理 |
| --- | --- |
| [腾讯校园招聘](https://join.qq.com/) / [腾讯招聘](https://careers.tencent.com/) | 可取得官方页面标题，正文依赖JS；可作为官方导航，不报告站内岗位数或“刚同步”。 |
| [字节跳动校园招聘](https://jobs.bytedance.com/campus/) | 可读到校园招聘与城市/职位搜索说明，但部分内容出现渲染占位；可导航，不把占位内容抽成岗位。 |
| [阿里巴巴集团招聘](https://talent.alibaba.com/) | 本轮 `/campus` 被重定向到此根入口；使用集团官网入口，不保证某个固定校招深链长期有效。 |
| [国家大学生就业服务平台](https://www.ncss.cn/) | 本轮工具只读到表单占位；可导航。其高校毕业生职位检索服务定位另由[教育部通知](https://www.moe.gov.cn/srcsite/A15/s3265/202204/t20220406_614117.html)确认，不宣称本站获得其开放数据接口。 |

可交付的使用链路：选企业/校招入口 → 到原站查看具体岗位 → 用户主动返回并保存岗位名称、来源链接及允许本站处理的要求原文 → 生成本人研究卡。以后若该来源获得同步能力，才为这张卡启用变更提示。

企业主动提供公开岗位CSV/JSON/RSS/API也是可选起点；文件或feed须有明确提供方与使用范围，不能用网上搜到的数据包代替来源确认。这里是建议的合作方式，未声称上述企业已经提供此类feed。

## 待实施的数据与更新设计

以下为本站产品和工程建议，不是对某一供应商API的事实描述。

### 1. 建立来源登记，再接适配器

每个来源登记：来源ID、企业/租户范围、官方域名、负责人/授权依据、允许展示与缓存的字段、读取方式、失效条件、刷新约定。密钥保留服务端，前端只知道来源状态，不接收企业token。

只取公开发布且允许本站展示的职位。**ATS内部状态为open不自动等于允许面向公众展示**；内部、仅内推及未发布职位需要单独过滤。先完成一个合作企业的闭环，再增加来源数量。

### 2. 岗位当前版本与本人保存版本分开

- 岗位稳定键使用“来源ID＋租户/企业ID＋来源岗位ID”。不同来源同名岗位不直接合并，确认等价后仅建立关联，并保留各自出处。
- 保存来源原文/准许保留的摘要、官方链接、原始状态、来源更新时间、本站成功获取时间和内容哈希。职位名称、地点、职责/要求、薪酬原文各自保留来源，不把AI推断写成原始条件。
- 发布新版本时保留旧版本索引；若来源约定限制长期保存正文，则按约定只保留允许的字段、哈希及变更记录。
- “我的机会”固定保存用户当时看到的版本；最新职位版本可变化，本人的备注、材料、准备和实际求职事件不被覆盖。

### 3. 先可靠同步，再谈实时

先做增量轮询与完整对账。可将15–60分钟作为合作试点的待评估目标，实际周期根据来源限额、变动量、成本和授权约定决定，不能在接通前承诺。

有经过确认的**岗位**变更事件时，再增加验证签名、事件去重和重试后的推送更新，并保留补偿轮询。仅存在候选人或面试Webhooks，不足以实现岗位实时。

后台完成任务后再推送本站页面变更提示。浏览器每次刷新只读取本站缓存，不为每个用户直接请求供应商。需要后台任务/队列、来源游标、失败重试、任务审计与关闭入口；不能仅添加前端计时器。

### 4. 不把失败、缺失与关闭混为一谈

- 记录 `lastAttemptAt` 和 `lastSuccessfulSyncAt`；请求超时不能刷新“资料更新”时间。
- 增量请求没有返回某岗位，不代表关闭。只有明确关闭事件/状态，或来源承诺完整枚举下的已核对移除，才能形成对应状态；否则显示“上次获取后未确认”。
- 全量对账失败或只获取了部分分页时，不删除未出现的岗位。关闭后保留本人历史快照。
- 数据过期显示上次成功时间及“更新暂未确认”，不把网络故障标成“已停止招聘”。“来源报告开放”也不等于保证可投递或一定招人。

### 5. 用户看到的效果

企业岗位页：职位与企业优先显示，其次是地点/岗位类别、来源及时间。资料状态明确区分“合成示例”“历史资料”“来源报告开放”“来源报告关闭”“更新待确认”；点击可看原站。

我的机会页：出现“你保存后，来源更新了2处”这类可核对提示，展开旧/新字段，用户决定是否更新研究卡的来源字段。个人笔记和实际申请状态不随之改变；无变化不制造动态。

“同步岗位资料”按钮需展示最近成功更新、当前排队/进行中、成功或失败。没有配置来源时显示“官方查找/手动保存”，不放一个看似可用却只更新时间的刷新按钮。

## 上线前最小验收

1. 至少一个国内授权来源，能确认企业范围、公开发布范围及展示字段；有真实凭证的隔离验收记录。
2. 翻页完整性、断点/增量补拉、重试去重、来源关闭、权限撤销和失败不误删各走通一次。
3. 岗位更新后，本人原快照、笔记和求职事件不丢失；同源重复导入不重复建卡。
4. 页面时间能追到真实成功任务；没有配置或任务失败时，不显示“实时同步成功”。
5. 只接岗位数据的授权；本人申请进度要有独立授权方案后才能自动同步。默认不接企业候选人数据，也不扩大为自动投递。

当前最需要补齐的外部条件是合作来源及允许本站展示的范围，而不是再增加一批虚拟岗位。拿到一个来源后，适配器、版本更新与页面状态可以在现有历史库/研究卡关联基础上逐步实施。
