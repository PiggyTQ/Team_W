# 内容与任务设计（先于视觉实现）

当前基线skill-follow；本轮新增内容先确定目标—讲解—练习—证据，再按既有蓝黄品牌实现。

服务告警目标：定义每分钟有效请求/5xx错误分母，计算比例；区分CPU原因线索与用户症状；在连续时间线上修改比例阈值、最小样本、持续时间，判断pending/firing/恢复、低流量和缺数据；按约束选择合理策略并交接证据与未知。

教学用上传服务12个连续分钟，学习/跟随/排错/独立/检验分别换请求量和坏请求数。每条记录是该分钟的区间计数，不是累计counter；错误定义5xx，超时若未进入该计数则须另补。每分钟末评估，for=2m表示首次满足后持续到两分钟以后，三个相邻评估点才firing。缺数显式unknown并重置本教学模型计时；这是预先聚合教学模拟，不是完整PromQL运行时或真实抓取缺样的等价实现。不用CPU决定唯一行动。

练习：同屏数据趋势与表、规则输入、逐分钟状态及可核对的指标/触发答案。确定项逐项反馈；开放说明用影响、证据、噪声/检测延迟、缺数/低流量与责任/复核时间五项rubric本人复核，不用关键词判定根因或策略优劣。允许满足行为约束的不同规则。保存各任务输入、提示、运行结果和复核。

SQL：保留实际查询运行，最终改为方法选择+过滤影响+新数据输出核对，证据仅支持这些行为。决策：取消两次组合数，最终覆盖OR漏项、无关合并与新参数逐格动作。交接：最终覆盖证据支持范围、授权/执行与新日志的事实/未知分类，不以自由字数认证真实判断。

版本：四条代表技能检验升v2，v1原题/评分仍可供旧客户端请求，原记录不改写；新草稿显式复制阅读与原稿，不复制伪造assessment。树按同技能历史真实通过继续显示，复测v2不再次授叶。未过定向回到方法/例子，改用不同练习输入再试。

综合：复用服务故障实践项目入口与下载的本次规则/时间线/复核产物，覆盖服务信号、日志关联、交接；项目自查不自动授其他芽叶。

依据：已阅读CMU alignment中的目标/活动/评价对应与应用任务，MDN技能检查与行星数据综合挑战的起始材料/任务要求/提示，Microsoft客户方案挑战的分阶段工作簿产物；Google SRE监控章的四信号、症状/原因及可行动告警，Prometheus规则for/pending/firing/keep_firing_for和规则测试的评估间隔/缺样标记。原创合成数据和本站结构为自主设计，不复制来源课程。
