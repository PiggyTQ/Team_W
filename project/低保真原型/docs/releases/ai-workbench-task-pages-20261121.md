## 页面与业务

| 页面 | 直接可用的内容 | 实际落点 |
| --- | --- | --- |
| `/assistant/next-step` | 已保存目标/全计划预算，本次方向/时间假设，选1—3项原任务，按需选用原文与反馈，讨论取舍 | 服务签发的建议绑定到可编辑草稿，回原计划编辑、预览、本人确认；更新原任务，不生成副本 |
| `/assistant/compare` | 明确选择双方，同维展示日常任务、典型产物、协作、入门实践；关注点调整可见顺序；可选本人确认材料 | 职业介绍/技能树/讨论笔记；不写入主目标，不输出个人适合度评分 |
| `/assistant/expression` | 单件作品/经历，明确勾选片段，实际状态，原文、贡献和缺项，用途及未核对自述 | 建议形成来源绑定候选，回个人评估编辑与影响预览；应用后仍待本人确认，确认后报告/简历方可采用 |

首页三个起点是实际链接。自由聊天、旧查询迁移、历史改名/归档/恢复/删除、本人笔记保留。归档讨论须恢复后继续。每个任务、职业组合、作品使用独立讨论身份，问题与所选资料随身份恢复；网址只含任务路径和不透明讨论 ID，不写入私人正文。历史、刷新、后退及业务草稿返回都恢复同一任务页。学习 Tutor 继续复用原讨论，没有新增常驻侧栏。

## 数据与安全边界

- `discussion.task` 严格白名单保存页类型、职业组合、对象身份、关注点、用途、时间与本次自述；长度、类型、职业身份和12引用上限均受校验，旧讨论不要求新字段。
- 临时方向/时间/用途/自述成为明确的 `unverified_discussion_input` 来源，参与服务端依据指纹和外发授权；没有自动改变真实目标、预算或确认材料。
- 职业对照投影复用 `model.js` 与 `career-detail-content.js`。前端和模型取得相同的服务端公开资料、出处、版本及内容指纹；O*NET 仅作职业功能参考，练习是站内模拟建议。双方缺一、相同职业、缺任一公开投影时拒绝完整比较。
- 资料目录只返回元数据、公开职业投影及明确选中且指纹有效的私人正文；选一个作品不会选用所有部件。成果页不接受其他对象的片段，公共课程介绍不能转成个人经历候选。
- 资料/对象/用途/时间改变后清除本次授权，旧回答停止参与新问答，来源绑定稿失效并保留原稿。最多使用同依据最近6条未确认问答。
- 原业务版本检查、预算/依赖/日期校验、草稿修订、预览有效期、本人确认及幂等回执复用。改日期不释放预算，明确延期状态才按原 `usedHours` 规则计算。
- 缺模型时仍可保存问题、查看选中内容、职业对照和明确标注的原文手动稿。没有合法结构化建议不伪造模型建议 ID；草稿不直接成为已确认经历、完成或技能掌握。
- 保留失败输入、取消和晚到保护；资料读取失败提供实际重读操作。填写临时说明不重复拉取整个目录，限流与费用保护未放宽。

三小时场景：仅填写假设时预算保持4小时；明确选中两项原任务→授权→本地受控建议→绑定稿→原计划预览→本人确认，原ID保留、两项变为1.5小时，刷新回执不重复创建。

成果场景：只选择第一件产物和本人贡献→用途/自述保留未核对属性→建议绑定候选→原个人评估编辑/预览/应用，候选仍为待确认；本人确认后报告预览与简历事实源均能采用。第二件作品原文未进入本次模型请求。

职业比较：两方公开投影进入同一模型证据包；未选本人材料不分析个人适合度。交换双方切换独立组合，交换回来恢复问题；关注点改变首行，真实目标不变。
