## 内容严密性先修四个实例

### 前端 让验收表与实际演示一致

案例输入承诺提交/成功/失败和防重复，但`CareerArtifactExamples.jsx`的FormExample仅同步检查邮箱格式。空值与abc都返回格式提示，和验收表“空值提示必填”也不一致。

优先修空值/非法格式的差异，再选择：增加明确标注的本机状态模拟，或将未演示状态标为待设计/另测。不能把格式符合叫提交成功，也不需要为职业预览搭真实报名后端。[MDN表单验证](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Form_validation)区分必填与格式要求，并明确客户端检查不能代替服务端校验。

### 数据工程 用内容证据解释重跑一致

`engineering.deliverables[1].example.rows`里run1/retry只有目标4行、重复0，却称“一致”；这些只能支持数量/唯一性检查，不能证明四条内容相同。

补4个稳定ID及一个关键字段的前后对照，或明确规范化字段与排序后的摘要；再给“仍是4行、某字段却被覆盖”的反例。固定输入批次/分区和失败不发布也要能从材料检查。[Airflow创建任务原文](https://airflow.apache.org/docs/apache-airflow/3.4.0/best-practices.html#creating-a-task)要求重跑产生相同结果，并固定所读写的分区。

### 运维 避免把分母一致说成请求数相等

`ops.deliverables[0].checks[0]`写“窗口、分母一致”，而三行例子恰好都1000请求，容易误教成请求量必须相同。

改为“窗口长度、错误定义与请求范围可比；分别保留各窗口请求量”。补一个请求数不同仍可计算的例子，以及错误率回落但核心报名流程仍失败的分支。恢复条件/负责人用明确的演练约定，不写成通用生产阈值。[Google SRE的SLI与聚合说明](https://sre.google/sre-book/service-level-objectives/)强调测量窗口、包含请求及聚合口径。

### 测试 示范与独立尝试使用不同输入

`testing.practice.brief`要求遮住实际列独立写预期，但上方预期列已经公开。可以作为读懂示范，不能据此宣称独立推演。

保留99.99/100/100.01完整示范，另给一个金额仍以分计的新门槛小变式，用户先写预期再看对照。预设缺陷“四舍五入”需注明按整数元取整后判断，避免精度含混；边界样本不是充分测试整个系统。[ISTQB CTFL §4.2.2](https://istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf)

## 十方向怎样丰富而不堆长文

每个方向只增加一个具体判断分岔；保留“输入—本人判断—小产物—检查—限制”，职业体验不扩成第二套技能课程。

| 方向 | 最有价值的一小步增补 |
| --- | --- |
| 数据分析 | 追踪一条同ID后被撤回的记录，解释为何先取最新再排除；追问现有渠道表能否证明流量下降。 |
| 人工智能 | 增加“引用确实存在但不支持结论”的变式；如继续承诺关键词基线比较，就提供两方案同题记录，否则收窄承诺。 |
| 网络安全 | E1—E3补日期/时区，说明20次失败窗口是否包含E1；请用户写出找谁补哪条证据，仍不从新设备推定入侵。 |
| 运维工程 | 把恢复拆成技术指标、核心流程、后续观察，补一个回退后仍异常的升级分支。 |
| 前端开发 | 空值、格式错误、等待、成功/失败各自有可见真实/模拟状态，修正不丢输入。 |
| 后端开发 | 在已有身份/对象矩阵上补同对象“可读但不可改”的动作维度，不将owner相等概括成全部授权。 |
| 数据工程 | 同行数、异内容的重跑反例；隔离批次不发布给下游。 |
| 软件测试 | 新门槛、先写预期、再看演练实际、形成可复现缺陷；保留未测范围。 |
| 通用软件开发 | 给一条优惠叠加的新需求，先澄清约定，再加一个检查，不只重复函数说明。 |
| IT实施交付 | 明确写入冻结假设，切换后有新报名时如何回退；摘要具体比较哪些字段、采用何种规则。 |

可增加两个可选职业认知追问：“这项工作里我愿意继续做哪部分？”“哪种困难值得再体验？”它们是本人偏好记录，不是能力结论，不默认进入AI、报告或简历。
