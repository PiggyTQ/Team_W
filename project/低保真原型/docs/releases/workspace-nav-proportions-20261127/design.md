# 英文工作区：导航比例实施前设计

用户要求用英文检查侧栏过窄、导航文字拥挤，并借鉴成熟网站的比例。本轮以改前隔离页面实拍作为现状，不另造用户截图。

## 参考与判断

- [Atlassian Navigation System：SideNav](https://atlassian.design/components/navigation-system/layout/code) 的默认宽度为320px，并将导航与正文作为独立布局区，提供折叠及尺寸约束。
- [IBM Carbon v10 UI Shell规范](https://v10.carbondesignsystem.com/components/UI-shell-left-panel/style/)给出256px侧栏、16px侧向留白及独立图标槽。这是有版本的参考规范，不冒称所有当前Carbon网站都只有一个宽度。
- [Atlassian Grid](https://atlassian.design/foundations/grid)区分内容宽度、视口断点与导航区域；正文不能只随侧栏扩大而无限被挤压。

两种系统的数值提供参考范围，不代表要照搬某个网站。本站菜单文案较长，还包含目标与伙伴区域，且已有76px折叠轨道。方案采用同宽的中英桌面壳，在256–320px参考范围附近按屏幕调节，不靠缩小英文或隐藏关键文字解决拥挤。

## 预期比例

| 视口宽度 | 展开侧栏 | 说明 |
| --- | --- | --- |
| 721–1023 | 240px | 紧凑桌面让长词组自然分行，保留正文空间。 |
| 1024–1279 | 256px | 接近Carbon参考宽度。 |
| 1280–1599 | 280px | 1366常用桌面，约占20.5%。 |
| 1600–1919 | 296px | 1616桌面约占18.3%。 |
| 1920及以上 | 320px | 较大桌面稳定导航宽度，正文保留原最大阅读宽度。 |

这些是实施候选值，最终以英文真实标签、正文和容器回流实测确认。折叠仍为76px，既有偏好、快捷键、提示与返回行为保留。720及以下继续使用可打开的完整文字抽屉，不把桌面展开宽度硬塞进手机正文。

## 导航文字与内部节奏

导航文字15px、图标独立22px槽位，间距12px。正常单行；长词组在空格处自然分两行，行距约1.45。高于1050px的桌面使用至少48px菜单行；较矮桌面使用至少44px行与横向紧凑伙伴区，优先保证八个主入口可见。首次实测1366×900通过，1616×960的常规伙伴区仍挤掉最后两项，因此将紧凑高度范围扩至1050px。主菜单不以省略号隐藏名称，也不把单词从中间硬拆开。伙伴的原对话、休息、隐藏与互动入口保留，不额外放大图片。

主区、底部流程栏与顶部搜索始终使用同一真实侧栏宽度；折叠、路由变化或打开Tutor后重新分配空间。英文切换不改变侧栏宽度，避免整页再次横跳。验证中英文、常用宽度、折叠/恢复、窄桌面/手机、正文滚动和草稿。

## 文件与验证方式

先保留baseline实际页面与结构示意，再对公共壳做局部修改。当前宽度存在多处旧规则：sidebar-layout默认224px，workspace-dashboard再覆盖244px，warm-workspace再覆盖220px。实现必须统一最终生效值，不能只改最早规则。

本轮不改业务状态、职业/学习数据和AI流程，不部署生产。实际截图和验收记录另存，不把本文件和structure.svg当作最终页面。

## 实测后的必要回流调整

768px窗口在侧栏加宽后暴露两项原有正文问题：职业模式页签横排挤掉标题宽度，以及固定筛选侧列后仍强排两张职业卡片。最终按正文容器回流：900px以下将标题/页签、筛选/结果依次上下排列，筛选字段在紧凑桌面使用两列；640px以下职业卡片单列。导航文案和职业正文都保留可读宽度，不能仅以没有横向滚动判断比例通过。

折叠截图还显示旧24px品牌槽与当前154px完整Logo不匹配，搜索覆盖字样。为完整Logo预留154px实际槽位和18px间距；76px折叠导航及正文位置继续保留。
