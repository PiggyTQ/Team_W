# U01 成果舞台与后续动效分镜

2026-10-17，v2。本说明替代 v1 成果区的横向轨道布局；首屏上下分区、正式 PRD 功能范围、15 主模板与 27 正式视图保持原约束。设计参考来自 [Pier Gorelli 首页 02 区](https://piergorelli.com/#work)，详见[布局与关键帧分析](../参考调研_20261017/PierGorelli_02/02区布局与关键帧分析.md)。参考的内容与动效不构成新的产品需求。

## 本轮已实现

首屏继续独立讲用途。下方“规划，会留下什么？”改为单一成果舞台：桌面左侧约三分之一放序号、标题、简短用途和形成过程，右侧约三分之二展示可读的成果；底部目录切换五种成果，箭头有首尾边界。手机改成说明、三态按钮、画布、目录的纵向排列。

默认先显示成果，让第一次访问的人立即知道网站会留下什么。需要理解过程时再点“起点／整理／成果”。选另一成果时恢复它的成果态，避免新访客切换后只看到未完成的输入。两套控制分别表示“看哪个成果”和“这个成果如何形成”，不把它们做成产品必须依次完成的主线进度。

|成果目录|起点：问题与输入|整理：依据和状态|成果：可回看的产物|
|---|---|---|---|
|职业要求|比较想解决的问题与两类工作|任务、产物、待验证问题|方向比较卡|
|我的材料|课程项目及本人负责部分|原文、本人贡献、确认边界|本人经历单|
|差距与未知|职业要求及已有材料|已有相关材料、缺产物、未知|差距对照单|
|本周行动|一个疑问及合成3小时预算|缩小范围、预计投入、交付标准|预计2小时＋1小时余量的行动安排|
|成长报告|选择理由、产物、贡献与未知|选择、行动、下一步|阶段探索报告结构|

所有 15 个状态均为合成案例，不读取本人资料、不运行真实 AI、不改变本人计划或报告。材料增加不等于能力提升，预算是预计投入，报告预览不代表已完成实践。这里采用 HTML/CSS 结构呈现，不需要收集照片或视频；后续若加入媒体，仍使用全黑占位。

## 操作与返回

- 五个目录按钮和前后箭头切换成果；首项上一项、末项下一项禁用，不循环。
- 画布可获取键盘焦点，左右键切成果，Home / End 到首尾；三态控制使用原生按钮，可 Tab 和 Enter 操作，选中状态明确。
- “查看完整合成示例”打开当前成果对应的示例阶段；关闭或 Esc 返回仍保留当前成果和形成阶段。开始规划进入原有模拟登录，取消不重置成果预览。
- 本成果区当前没有横向滚动卡片、自动播放、滚动固定或连续形变。不要将本轮称为原站动效复刻完成。其下职业方向区已另行实施[展廊v3](首页卡牌路径与方向展廊说明.md)，不能把两个区块的实现状态混写。

## 后续正式视觉实现的动效计划（尚未实施）

建议先做**单个成果的三态连续变化**，再评估是否需要滚动固定。默认成果态与人工目录始终保留，读者可以直接查看结果。不能为欣赏动效强迫读完五次完整演变。

以下为本项目建议值，区别于原站实测/源码值：

|局部进度|画面与信息|拟用属性及约束|
|---|---|---|
|0—.25|问题、两项输入形成清晰骨架|opacity＋最多12px位移；不逐字打字，不遮住来源|
|.25—.60|输入归入固定字段，显出依据、缺项和未知|同一纸面和行位置连续；优先transform/opacity；状态文字立即可读|
|.60—.85|产物结构覆盖整理层|局部遮罩或裁切，不制作全屏扫光；正文不参与缩放失真|
|.85—1|成果静止可读，保留下一步入口|停止持续渲染；来源、未知、合成标识始终可见|

若点击切换，建议总过渡 240—400ms，淡出/进入轻微重叠；用户连续点击时从当前位置中断并响应最后选择，不能排队播放。键盘、减少动态效果模式直接切换，焦点不随动画漂移。不要在aria-live逐帧播报，只播报最终成果和阶段。

若原型验证确认需要滚动演示，可在足够宽高的桌面试验**一个舞台、当前成果约1—1.5屏**的局部滚动映射；五种成果通过目录选择，不默认追加8屏固定区。这是待验证方案，不是已敲定的产品行为。固定从舞台顶部进入可视区后开始，完成当前成果即解除；要有“直接看成果”和“继续浏览首页”入口，后者能离开固定区而不丢焦点。向上滚动必须连续可逆，点击目录不与滚动脚本争夺位置。

宽度≤720px、较矮窗口、放大后容纳不足、减少动态效果或脚本不可用时，应回退为自然纵向阅读/可操作静态内容。未来固定断点由实测容纳空间决定，不直接复制原站1024×600。当前 React 格局可作为静态基础；若后续改成滚动隐藏，需另外提供无需脚本也能读取五种成果的回退。

工程上保留 `data-outcome-stage`、`data-outcome-phase`、`data-outcome-canvas` 作为状态/渲染边界。未来动效层只读演示状态，不接业务更新。框架可采用清理完备的GSAP时间线或原生实现，本轮没有安装新动效依赖。避免逐帧改布局宽度、大面积滤镜、WebGL背景及全站滚轮接管；组件卸载、断点切换、减少动态效果变化时须恢复样式并销毁监听。

正式加入后需复测：向前/反向/快速滚动、点击打断、键盘跳项、浏览器返回锚点、窗口缩放、200%放大、触屏取消、固定区退出、减少动态效果、长中文及脚本失败回退。未经这些检查，不将连续动效标为完成。
