# U05 企业与岗位 / 我的机会：布局与数据边界

更新：2026-10-17。已实装灰阶交互线稿，未接入真实招聘源、企业服务或投递服务。

本说明取代旧版把两个标签都画成同一组本人研究卡的安排。依据为最新正式《16_Teal求职执行增补》FR42/FR43、《15_全链路评估与低保真启动规格》5.4及U05页面规则，并对照页面清单、链路矩阵与UX42。继续使用U05模板内的标签与模式，不增加一级页面，不改变15模板、27视图或43项需求的范围。

## 两个标签各自解决什么问题

|项目|企业与岗位|我的机会|
|---|---|---|
|用户问题|有哪些具体工作值得研究，原文和来源是什么？|我关注了什么，正在准备什么，实际发生过什么？|
|内容来源|当前仅两个明确标注的原创合成目录条目；以后可接获准且说明时效的数据源|本人主动加入、手工输入或允许处理的私有研究卡；PT场景的卡片是显式载入的示例|
|页面布局|用途与来源提示 → 筛选 / 岗位列表 / 来源详情；字段比较按需展开|个人概览 → 我的研究卡列表 / 选中详情；概览来源、要求对照、笔记准备、申请进展切换|
|主要操作|查找、筛选、阅读、比较、加入我的机会|编辑私人笔记、准备预检、继续原任务、制作简历、记录本人事件、归档与恢复|
|不自动发生|浏览不收藏，收藏不申请、不创建任务、不切换主目标|查看、导出、准备完成不推断已投递，不把单次求职结果改成能力结论|

“企业与岗位”没有本人申请时间线和私人准备信息；“我的机会”不自动展示目录里的所有岗位。两页有明确的互达入口。手机按用途、筛选、列表、详情排列；详情按钮可定位到下方详情，不依赖桌面三栏布局。

## 关联方式和后续内容填充

目录条目与个人研究卡是两类对象。点击“加入我的机会”时生成个人卡ID，记录来源 `catalogId` 和加入时的 `sourceSnapshot`。同来源重复加入只打开已有卡，已归档记录也可找回。

后续填充真实内容时，目录可更新企业资料、岗位职责、条件、来源与有效期；本人笔记、任务、简历版本和申请事件继续保留在个人卡中。更新目录不能覆盖保存时的来源快照，不能把私人输入发布到目录。当前原型尚未实现外部目录更新/下架同步服务；该段是后续接入约束，不冒称现有服务能力。

本人手工输入只进入个人研究卡。编辑本人允许处理的原文，不改变目录原文或初始快照。本人事件通过个人卡ID关联，准备任务仍引用原来的taskId，纳入同一预算。归档/恢复只改变个人卡的归档状态，保留笔记、事件、材料和任务；不会删除目录条目，也不自动取消原任务。

保留本机已有研究卡、事件与任务，不清空用户存储。原PT05的两个合成卡按原ID与明确的合成来源识别为已保存，不按标题或企业名合并私人输入。目录筛选条件刷新后保留；清空条件同步保存。回看指定来源时优先展示该来源，避免被旧筛选挡住。

## 可操作浏览路线

1. 在“企业与岗位”输入关键词或筛选方向；零结果可重置。打开详情或比较两个示例，均不生成个人记录。
2. 点击“加入我的机会”，查看成功回执；再点“在我的机会查看”，进入对应个人卡。
3. 编辑私人笔记，查看要求与已确认材料，或通过准备预检引用同一计划任务。取消预检不创建任务。
4. 在S2演示中手工记录申请、面试或结果及材料快照；研究准备状态保持独立。原型不会真实投递。
5. 回看来源目录，原始目录内容不带私人笔记；回个人卡可归档、确认或取消，之后恢复历史。

全站模板/27视图、既有页面体验与前后导航回归通过；构建与5项模型检查通过。这些仅验证所测本机原型。正式数据授权与时效核验、服务端个人权限/存储、外部目录同步、真实AI检索与真实投递仍需服务支持，不能将本地合成流程当作真实功能已上线。
