# 目标计划、技能地图入场与滚轮修复

日期：2026-11-19。依据用户反馈：目标计划与职业技能地图动画仍有问题，部分页面无法使用鼠标滚轮。

## 实施前修订

- 目标计划：将带边框、背景和裁切的整个工作台视为入场模块。避免容器已显示、内部两半仍从裁切边缘移入的割裂效果；原有模块内幕布保留。
- 技能地图：等待异步主体与关键树图就绪，再让标题、树图、技能路径沿同一错峰时间轴入场。等待时可见的加载状态正常显示，已有模块不先播放一遍。错误、超时或用户交互可立即结束等待。
- 滚轮：页面内的资料列表、计划明细、聊天内容等先使用自身滚动范围，到达边界后交给主页面。侧栏、弹窗、浮层仍保留各自滚动边界。不增加 JavaScript 滚轮拦截或模拟滚动。
- 核查方式改为真实浏览器滚轮输入并检查实际滚动位移，覆盖正文、嵌套面板、面板边界与短窗口；不再以派发 wheel 事件和动画停止代替滚动验证。

状态：修复完成，实际分镜和移动端截图已目视核对。初版截图与验收保留为历史记录。

## 修复结果

目标计划不再将 `.plan-stage` 拆开动画，而是让整张带裁切的卡片连同背景、边框和内部两栏一起浮现，原幕布的层级与局部裁切继续保留。只等待显式标记的页面加载状态，普通状态摘要和屏幕阅读器播报不再被识别为加载中。

技能地图中先准备好透明的模块，等异步主体和标记的关键树图完成解码，再统一设置动画开始时间并错峰播放。模块不分批重播。加载失败、最长 4 秒等待、页面交互、快速导航、窗口变化和减少动态效果均能取消等待并恢复已就绪内容。

资料侧栏、计划明细／摘要／编辑区、日程侧面板和聊天区域保留自身滚动，竖向滚到边界后允许交给主区。实际复现的 AI 空白聊天卡片从完全截住滚轮变为正常带动主区滚动。桌面工作区由主区和侧栏负责滚动，约束外层窗口，修复主区滚到底后整个窗口继续偏移的现象；返回公开首页和手机宽度时使用正常窗口滚动。

## 验证

- [专项浏览器检查结果](修复验收/检查结果.json)：14 项通过，运行时错误 0。包含 9 个工作区页面 × 6 个正文落点，共 54 处真实鼠标滚轮输入，逐次核对实际滚动位移；全部九个导航入口入场与普通状态提示不误触发等待也通过。
- 资料列表先滚动自身，上／下边界交给主区；18 条合成目标的计划明细列表滚动及边界交接通过；原幕布切换保留。
- 地图关键图片人为延迟时，标题、树图与技能路径均等待，图片就绪后共用同一个动画开始时间。等待期间快速切换页面不残留旧动画。
- 入场中真实滚轮可以结束动画并滚动内容；桌面滚到底顶部和侧栏不偏移；公开首页恢复窗口滚动；390 手机宽度的目标计划、技能地图、AI 工作台实际滚动通过。
- 系统减少动态效果通过。原有芝士匀速转场、模块幕布及排期入口、计划制定／执行、动画中切换减少动态效果四项回归通过。路由恢复 8 项通过。
- `npm run build` 通过，双语条目 8418、`exactMissing=0`。原有构建提示仍保留；没有部署或运行全量后端测试。

可复跑的浏览器脚本为 [workspace-motion-scroll-browser.mjs](../../低保真原型/tests/workspace-motion-scroll-browser.mjs)，使用本地演示页面和合成记录，不使用真实账户。
